    Glossari tècnic
    Terme Definició
    Autenticació Procés de verificar la identitat d'un usuari (login/logout).
    Autorització Procés de determinar quines accions pot realitzar un usuari autenticat.
    Component Blade Classe reutilitzable que encapsula lògica i vista per a elements d'interfície, amb sintaxi moderna <x-nombre>.
    Cookie Xicotet fitxer de text emmagatzemat en el navegador de l'usuari per a mantindre informació.
    CSRF Cross-Site Request Forgery - atac que explota la confiança d'un lloc web en un usuari autenticat.
    Disc d'Emmagatzematge Ubicació configurada on Laravel guarda fitxers (local, public, s3).
    Enllaç Simbòlic "Portal" que connecta public/storage amb storage/app/public per a fer els fitxers accessibles públicament.
    Formulari Web Element HTML que permet als usuaris enviar dades al servidor de manera estructurada.
    Laravel Breeze Paquet oficial de Laravel que implementa autenticació completa amb vistes, controladors i rutes preconfigurades.
    Missatge Flash Dada emmagatzemada en sessió que només persistix per a la següent petició, útil per a notificacions.
    Middleware Capa de programari que processa les peticions HTTP abans que arriben als controladors.
    Rate Limiting Tècnica que limita la freqüència de peticions per a previndre abusos.
    Sanitització Procés de netejar i validar dades d'entrada per a previndre atacs d'injecció.
    Sessió Mecanisme que permet mantindre informació de l'usuari entre múltiples peticions HTTP.
    Slot Variable especial en components Blade que representa el contingut passat entre les etiquetes del component.
    Storage Facade Interfície de Laravel per a gestionar fitxers (guardar, llegir, eliminar) de forma consistent en diferents discos.
    Validació Procés de verificar que les dades introduïdes complixen els criteris especificats.
    FAQ (Preguntes Freqüents sobre la Pràctica)

    • Per què és important la protecció CSRF en els formularis?

      CSRF protegix contra atacs en què un lloc maliciós realitza accions en nom de l'usuari autenticat sense que ho sàpia, explotant la confiança del navegador.

    • Quina és la diferència entre validació del frontend i del backend?

      La validació del frontend millora l'experiència de l'usuari amb retroalimentació immediata, però la validació del backend és essencial per a la seguretat i ha de ser la font de veritat.

    • Com funciona el sistema de validació de Laravel?

      Laravel proporciona regles de validació predefinides i permet crear regles personalitzades, i retorna errors estructurats que es poden mostrar fàcilment a l'usuari.

    • Què són les sessions i per què són importants?

      Les sessions permeten mantindre informació de l'usuari entre peticions HTTP (que és stateless), cosa essencial per a funcionalitats com ara carrets de la compra o estats de login.

    • Quan he d'usar middleware personalitzat?

      Quan necessites aplicar la mateixa lògica a múltiples rutes (logging, autenticació, rate limiting) o quan vols mantindre el codi organitzat i reutilitzable.

    • Com puc millorar la seguretat dels meus formularis?

      Usant protecció CSRF, validació robusta, sanitització de dades, rate limiting, i seguint les millors pràctiques d'OWASP per a formularis web.

    • Quina és la diferència entre autenticació i autorització?

      L'autenticació verifica "qui eres" (login), mentre que l'autorització determina "què pots fer" (permisos i rols).

    • Error "Les imatges no es mostren en el navegador" després de pujar-les

      Verifica els passos següents:

      1. Has executat sail artisan storage:link per a crear l'enllaç simbòlic
      2. El fitxer s'ha guardat en storage/app/public/products/ amb store('products', 'public')
      3. En la vista uses asset('storage/' . $product->image) (no asset('public/storage/...'))
      4. Els permisos del directori storage/app/public permeten la lectura (755)
      5. Verifica que el fitxer existix amb ls -la storage/app/public/products/

    • Error "419 Page Expired" en enviar formularis després d'instal·lar Breeze

      Verifica els passos següents:

      1. Tots els formularis tenen la directiva @csrf dins de l'etiqueta <form>
      2. Neteja la memòria cau amb sail artisan config:clear i sail artisan cache:clear
      3. Esborra les cookies del navegador per a localhost
      4. Verifica que .env té APP_KEY generada (executa sail artisan key:generate si no)
      5. Recarrega la pàgina amb Ctrl+F5 (o Cmd+Shift+R en Mac) per a netejar la memòria cau del navegador.

    • Per què tinc dues sintaxis de layouts diferents (@extends i <x-app-layout>)?

      És completament normal en projectes que integren Laravel Breeze:

      1. Les pàgines públiques usen @extends('layouts.public') (layout que vas crear en pràctiques anteriors)
      2. Les pàgines d'administració usen <x-app-layout> (layout generat automàticament per Breeze)
      3. Totes dues sintaxis són vàlides i poden coexistir en el mateix projecte
      4. Breeze usa components Blade (sintaxi moderna), mentre que el teu layout públic usa sintaxi tradicional
      5. En projectes nous, es recomana triar una sintaxi, però en projectes existents és normal tindre'n totes dues

    • Error "Call to undefined method store()" en pujar fitxers

      Verifica els passos següents:

      1. El formulari té enctype="multipart/form-data" en l'etiqueta <form>
      2. El camp input és de tipus file: <input type="file" name="image">
      3. Uses $request->file('image') (no $request->input('image'))
      4. Valides el fitxer amb 'image' => 'required|image|mimes:jpeg,png,jpg|max:2048'
      5. Has importat la facade use Illuminate\Support\Facades\Storage; si uses mètodes de Storage

    • Les dades del carret es perden en tancar el navegador

      Este és el comportament esperat de les sessions:

      1. Les sessions per defecte expiren quan es tanca el navegador
        1. Si vols persistència, has d'usar la taula product_user (com en la wishlist)
      3. El carret usa sessions perquè és temporal i s'ha de buidar després de la compra
      4. La wishlist usa base de dades perquè és permanent i ha de persistir entre sessions
      5. Per a ampliar el temps de sessió, modifica SESSION_LIFETIME en .env (en minuts)

    • Com depure errors en els middleware personalitzats?

      Usa estes tècniques:

      1. Afig Log::info('Mensaje de debug', ['data' => $variable]) en el middleware
      2. Revisa els logs amb tail -f storage/logs/laravel.log
      3. Usa dd($request->all()) per a veure què rep el middleware
      4. Verifica que el middleware està registrat en bootstrap/app.php
      5. Comprova que s'aplica a les rutes correctes amb sail artisan route:list

    L'objectiu d'esta pràctica és completar la botiga en línia implementant un sistema complet d'autenticació d'usuaris, formularis segurs amb protecció CSRF, validació robusta de dades, gestió de sessions i middleware personalitzat.     Esta pràctica representa la culminació del projecte de botiga en línia iniciat en la Pràctica 1. S'integraran totes les funcionalitats apreses (rutes, controladors, vistes, models, relacions) afegint la capa de seguretat i gestió d'usuaris necessària per a una aplicació web professional.

    Continuació de la Pràctica 3¶

    Esta pràctica està basada en la botiga en línia amb persistència de dades real creada en la Pràctica 3. S'hi afegirà autenticació d'usuaris, formularis segurs i protecció de rutes per a completar la funcionalitat CRUD.

    FASE 2: Preparar layouts per a la separació pública/privada¶

    En esta sessió implementarem un sistema de login i registre utilitzant Laravel Breeze. Abans d'instal·lar esta llibreria, és fonamental reorganitzar els nostres layouts existents per a evitar conflictes.

    1. Per què separar els layouts?¶

    Laravel Breeze crea automàticament un layout anomenat app.blade.php per a àrees autenticades (dashboard, perfil, administració). No obstant això, ja tenim un app.blade.php dissenyat específicament per a la nostra botiga pública.

    Conflicte imminent

    Si instal·lem Breeze sense preparar els layouts, sobreescriurà el nostre fitxer actual, i perdrem tot el disseny de la botiga pública.

    2. Canviar el nom del layout¶

    Crearem dos layouts independents, cadascun optimitzat per al seu propòsit:

    Layout Propòsit Característiques Usat per
    public.blade.php Botiga pública Navegació de productes, footer e-commerce Visitants no autenticats
    app.blade.php Àrea d'administració Dashboard, menú d'usuari, enllaços admin Usuaris autenticats

    Canviar el nom del fitxer app.blade.php

    Canviarem el nom del fitxer app.blade.php a public.blade.php perquè continga el disseny de la botiga pública. 

    mv resources/views/layouts/app.blade.php resources/views/layouts/public.blade.php

    3. Actualitzar les vistes públiques¶

    Ara actualitzarem totes les vistes públiques perquè usen el nou nom del layout.

    Vistes que cal actualitzar:

    1. resources/views/welcome.blade.php (pàgina principal).
    2. resources/views/contact.blade.php (pàgina de contacte).
    3. resources/views/cart/index.blade.php (carret de la compra).
    4. resources/views/categories/index.blade.php (productes per categoria).
    5. resources/views/categories/show.blade.php (productes per categoria).
    6. resources/views/offers/index.blade.php (productes en oferta).
    7. resources/views/offers/show.blade.php (productes en oferta).
    8. resources/views/products/index.blade.php (llistat de productes).
    9. resources/views/products/show.blade.php (detall de producte).

    Modifica

    Per a cadascuna d'estes vistes, busca la línia: 

    @extends('layouts.app')

    I canvia-la per: 

    @extends('layouts.public')

    Forma ràpida (amb comandaments) per a Linux:

    El comandament sed és una eina de Linux per a buscar i reemplaçar text en fitxers. És més ràpid que editar cada fitxer manualment. 

    # Actualizar welcome.blade.php
sed -i "s/@extends('layouts.app')/@extends('layouts.public')/g" resources/views/welcome.blade.php

# Actualizar contact.blade.php
sed -i "s/@extends('layouts.app')/@extends('layouts.public')/g" resources/views/contact.blade.php

# Actualizar vistas de carrito (si existe)
sed -i "s/@extends('layouts.app')/@extends('layouts.public')/g" resources/views/cart/index.blade.php 2>/dev/null || true

# Actualizar vistas de categorías
sed -i "s/@extends('layouts.app')/@extends('layouts.public')/g" resources/views/categories/index.blade.php 2>/dev/null || true
sed -i "s/@extends('layouts.app')/@extends('layouts.public')/g" resources/views/categories/show.blade.php

# Actualizar vistas de ofertas
sed -i "s/@extends('layouts.app')/@extends('layouts.public')/g" resources/views/offers/index.blade.php 2>/dev/null || true
sed -i "s/@extends('layouts.app')/@extends('layouts.public')/g" resources/views/offers/show.blade.php 2>/dev/null || true

# Actualizar vistas de productos
sed -i "s/@extends('layouts.app')/@extends('layouts.public')/g" resources/views/products/index.blade.php
sed -i "s/@extends('layouts.app')/@extends('layouts.public')/g" resources/views/products/show.blade.php

    FASE 3: Instal·lar i configurar Laravel Breeze¶

    1. Què és Laravel Breeze?¶

    Laravel Breeze és un kit d'inici d'autenticació minimalista que proporciona una implementació completa de:

    • Registre d'usuaris amb validació.
    • Login i logout amb sessions.
    • Recuperació de contrasenya amb correus electrònics.
    • Verificació de correu electrònic (opcional).
    • Actualització de perfil i contrasenya.
    • Vistes Blade predissenyades amb Tailwind CSS.
    • Rutes protegides amb middleware.

    Breeze és perfecte per a projectes que necessiten autenticació bàsica sense complexitat innecessària.

    Alternatives a Breeze

    Laravel també oferix:

    • Jetstream: Més complet, amb equips, 2FA i API tokens.
    • Fortify: Backend d'autenticació sense vistes.
    • Sanctum: Autenticació API per a SPA i aplicacions mòbils.

     

    Per a esta pràctica, Breeze és ideal perquè és simple i usa Blade (que ja coneixem).

    2. Instal·lar Laravel Breeze¶

    Laravel Breeze s'instal·la com una dependència de desenvolupament perquè només es necessita durant la configuració inicial.

    Executa el comandament següent per a instal·lar Breeze

    sail composer require laravel/breeze --dev
    Exemple de resposta 
    artur@pc_classe:~/development/laravel/MyShop$ sail composer require laravel/breeze --dev
.........

    3. Instal·lar l'stack d'autenticació Blade¶

    Ara instal·larem l'"stack" de Breeze amb Blade. Això generarà:

    • Controladors d'autenticació.
    • Rutes d'autenticació.
    • Vistes Blade per a login, registre, recuperació de contrasenya, etc.
    • Migracions per a taules d'autenticació.

    Important: Breeze sobreescriurà alguns fitxers

    Laravel Breeze reemplaçarà routes/web.php → Perdràs totes les teues rutes (productes, categories, ofertes).

     

    No et preocupes, en la FASE 5 restaurarem totes les rutes de la botiga.

    Executa:

    sail artisan breeze:install blade
