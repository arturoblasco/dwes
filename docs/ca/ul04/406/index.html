    9.6. Blade Components per a Layouts¶

    En les sessions anteriors vas aprendre a crear vistes amb Blade i components xicotets reutilitzables. Laravel Breeze (apartat 4) utilitza una sintaxi moderna de components per a layouts complets que pot resultar confusa si només coneixes la sintaxi tradicional.

    Els components Blade no sols servixen per a elements xicotets reutilitzables (com ara targetes de producte), sinó que també es poden utilitzar per a definir l'estructura completa de les pàgines. Laravel Breeze utilitza esta sintaxi moderna de components per als layouts.

    6.1. Components xicotets vs components de Layout¶

    En la Sessió 2 vas aprendre a crear components xicotets per a elements reutilitzables. Ara veurem com Laravel també usa components per a estructures completes de pàgina.

    6.1.1. Taula comparativa¶

    Per a entendre millor la diferència entre components xicotets i components de layout, esta taula mostra les seues característiques principals.

    Aspecte Components Xicotets Components de Layout
    Grandària Xicotets, específics Grans, estructurals
    Exemple <x-product-card>, <x-button> <x-app-layout>, <x-guest-layout>
    Propòsit Element reutilitzable Estructura completa de pàgina
    Ubicació Dins del contingut Embolcalla tot el contingut
    Aprés en Sessió 2 ✅ Sessió 4 (este tema)

    6.2. Sintaxi tradicional vs Sintaxi de components¶

    Laravel oferix dues formes de crear layouts:

    • la sintaxi tradicional amb @extends i @yield i
    • la sintaxi moderna amb components. Totes dues són vàlides i poden coexistir en el mateix projecte.

    6.2.1. Sintaxi tradicional (ja coneguda)¶

    Esta és la sintaxi que vas aprendre en la Sessió 2:

    <?php
{{ -- resources/views/products/index.blade.php -- }}
@extends('layouts.app')

@section('title', 'Productos')

@section('content')
    <h1>Lista de Productos</h1>
    <div class="grid">
        @foreach($products as $product)
            @include('partials.product-card')
        @endforeach
    </div>
@endsection

    <?php
{{ -- resources/views/layouts/app.blade.php -- }}
<!DOCTYPE html>
<html lang="es">
<head>
    <title>@yield('title', 'Mi Tienda')</title>
</head>
<body>
    <header>
        <nav><!-- Navegación --></nav>
    </header>

    <main>
        @yield('content')
    </main>

    <footer><!-- Footer --></footer>
</body>
</html>

    6.2.2. Sintaxi moderna amb components (Laravel Breeze)¶

    Esta és la sintaxi que Laravel Breeze genera automàticament:

    <?php
{{ -- resources/views/dashboard.blade.php -- }}
<x-app-layout>
    <x-slot name="header">
        <h2 class="font-semibold text-xl text-gray-800 leading-tight">
            Dashboard
        </h2>
    </x-slot>

    <div class="py-12">
        <div class="max-w-7xl mx-auto sm:px-6 lg:px-8">
            <h1>Contenido del Dashboard</h1>
        </div>
    </div>
</x-app-layout>

    <?php
{{ -- resources/views/components/app-layout.blade.php -- }}
<!DOCTYPE html>
<html lang="es">
<head>
    <title>{{ $header ?? 'Mi Aplicación' }}</title>
</head>
<body>
    @if (isset($header))
        <header class="bg-white shadow">
            <div class="max-w-7xl mx-auto py-6 px-4">
                {{ $header }}
            </div>
        </header>
    @endif

    <main>
        {{ $slot }}
    </main>

    <footer><!-- Footer --></footer>
</body>
</html>

    6.2.3. Comparació costat a costat¶

    Esta taula compara les característiques principals de totes dues sintaxis perquè pugues entendre les equivalències i decidir quina usar en el teu projecte.

    Característica Sintaxi Tradicional Sintaxi de Components
    Vista filla @extends('layouts.app') <x-app-layout>
    Contingut principal @section('content') ... @endsection
    Seccions amb nom @section('title') <x-slot name="title">
    Layout @yield('content')
    Usat per Projectes personalitzats Laravel Breeze, Jetstream
    Avantatges Familiar, simple Més potent, orientat a objectes

    6.3. Entenent¶

    La variable $slot és el concepte clau dels components de layout. Representa el contingut que es passa al component.

    6.3.1. Què és $slot?¶

    $slot és una variable especial que representa tot el contingut que col·loques entre les etiquetes d'obertura i tancament d'un component. És la forma de passar contingut al component.

    <?php
{{ -- Cuando escribes esto: -- }}
<x-app-layout>
    <h1>Mi contenido aquí</h1>
    <p>Más contenido</p>
</x-app-layout>

{{ -- Todo lo que está entre las etiquetas se convierte en $slot -- }}

    En el component, es reemplaça per eixe contingut:

    {{ -- resources/views/components/app-layout.blade.php -- }}
<div class="container">
    {{ $slot }}  {{ -- Aquí se insertará: <h1>Mi contenido aquí</h1><p>Más contenido</p> -- }}
</div>

    6.3.2. $slot vs @yield¶

    Són conceptes equivalents però amb diferent sintaxi:

    <?php
{{ -- Sintaxis tradicional -- }}
@yield('content')  {{ -- En el layout -- }}

@section('content') ... @endsection  {{ -- En la vista -- }}

    <?php
{{ -- Sintaxis de componentes -- }}
{{ $slot }}  {{ -- En el componente -- }}

<!-- Contenido entre etiquetas -->  {{ -- En la vista -- }}

    6.4. Slots amb nom¶

    A més del $slot principal, pots definir múltiples slots amb noms específics.

    6.4.1. Definir Slots amb nom¶

    Per a crear seccions específiques en el teu layout (com ara header, sidebar, footer), definixes slots amb nom que pots omplir des de les vistes que usen el component.

    <?php
{{ -- resources/views/components/app-layout.blade.php -- }}
<!DOCTYPE html>
<html>
<head>
    <title>{{ $title ?? 'Mi App' }}</title>

    {{ -- Slot para CSS adicional -- }}
    {{ $styles ?? '' }}
</head>
<body>
    {{ -- Slot para el header -- }}
    @if (isset($header))
        <header>
            {{ $header }}
        </header>
    @endif

    {{ -- Slot principal (contenido) -- }}
    <main>
        {{ $slot }}
    </main>

    {{ -- Slot para JavaScript adicional -- }}
    {{ $scripts ?? '' }}
</body>
</html>

    6.4.2. Usar Slots amb nom¶

    Des de la vista que usa el component, omplis cada slot amb nom usant l'etiqueta <x-slot name="...">. El contingut sense slot específic s'assigna automàticament a $slot.

    <?php
{{ -- resources/views/admin/products.blade.php -- }}
<x-app-layout>
    {{ -- Slot nombrado: header -- }}
    <x-slot name="header">
        <h2>Gestión de Productos</h2>
    </x-slot>

    {{ -- Slot nombrado: styles -- }}
    <x-slot name="styles">
        <link rel="stylesheet" href="/css/admin.css">
    </x-slot>

    {{ -- Slot principal (sin nombre) -- }}
    <div class="content">
        <h1>Lista de productos</h1>
        <!-- Contenido principal -->
    </div>

    {{ -- Slot nombrado: scripts -- }}
    <x-slot name="scripts">
        <script src="/js/admin.js"></script>
    </x-slot>
</x-app-layout>

    6.5. Per què coexistixen totes dues sintaxis en la pràctica?¶

    En la Pràctica 4, veuràs que usem totes dues sintaxis en el mateix projecte:

    6.5.1. Pàgines públiques (sintaxi tradicional)¶

    Les pàgines públiques de la teua aplicació poden continuar usant la sintaxi tradicional que vas aprendre en les primeres sessions.

    <?php
{{ -- resources/views/products/index.blade.php -- }}
@extends('layouts.public')

@section('content')
    <h1>Catálogo de Productos</h1>
@endsection

    Raó: Vam crear este layout nosaltres mateixos en pràctiques anteriors usant la sintaxi tradicional.

    6.5.2. Pàgines d'administració (sintaxi de components)¶

    Les pàgines d'administració creades després d'instal·lar Laravel Breeze usaran la sintaxi moderna de components que Breeze genera automàticament.

    <?php
{{ -- resources/views/admin/products/create.blade.php -- }}
<x-app-layout>
    <x-slot name="header">
        <h2>Crear Producto</h2>
    </x-slot>

    <form action="{{ route('products.store') }}" method="POST">
        @csrf
        <!-- Formulario -->
    </form>
</x-app-layout>

    Raó: Laravel Breeze genera automàticament app-layout.blade.php usant la sintaxi de components.

    6.5.3. És això un problema?¶

    ¿Tindre totes dues sintaxis en el mateix projecte pot paréixer inconsistent al principi, però en realitat és una situació molt comuna en aplicacions reals? No. És completament normal i reflectix un escenari real:

    • ✅ Projectes en evolució: Comences amb sintaxi tradicional, després afiges Breeze.
    • ✅ Equips de desenvolupament: Diferents desenvolupadors preferixen diferents estils.
    • ✅ Context diferent: Públic (tradicional) vs Admin (components).
    • ✅ Laravel ho permet: Totes dues sintaxis conviuen sense conflictes.

    Bona Pràctica

    En projectes nous, es recomana triar una sintaxi i usar-la de manera consistent. Però en projectes existents o en integrar paquets com Breeze, és normal tindre'n totes dues.

    6.6. Components de Layout de Laravel Breeze¶

    Quan instal·les Laravel Breeze, es creen automàticament dos components de layout principals:

    6.6.1. app-layout.blade.php¶

    Este és el layout principal que Laravel Breeze genera per a totes les pàgines que requerixen autenticació. Inclou navegació, header opcional i contingut principal.

    Ubicació: resources/views/components/app-layout.blade.php

    Propòsit: Layout per a usuaris autenticats (dashboard, perfil, admin).

    <?php
<!DOCTYPE html>
<html lang="{{ str_replace('_', '-', app()->getLocale()) }}">
    <head>
        <meta charset="utf-8">
        <meta name="viewport" content="width=device-width, initial-scale=1">
        <meta name="csrf-token" content="{{ csrf_token() }}">

        <title>{{ config('app.name', 'Laravel') }}</title>

        <!-- Fonts -->
        <link rel="preconnect" href="https://fonts.bunny.net">
        <link href="https://fonts.bunny.net/css?family=figtree:400,500,600&display=swap" rel="stylesheet" />

        <!-- Scripts -->
        @vite(['resources/css/app.css', 'resources/js/app.js'])
    </head>
    <body class="font-sans antialiased">
        <div class="min-h-screen bg-gray-100">
            @include('layouts.navigation')

            <!-- Page Heading -->
            @if (isset($header))
                <header class="bg-white shadow">
                    <div class="max-w-7xl mx-auto py-6 px-4 sm:px-6 lg:px-8">
                        {{ $header }}
                    </div>
                </header>
            @endif

            <!-- Page Content -->
            <main>
                {{ $slot }}
            </main>
        </div>
    </body>
</html>

    6.6.2. guest-layout.blade.php¶

    Este layout està dissenyat per a pàgines públiques on els usuaris no autenticats poden registrar-se o iniciar sessió. Té un disseny més simple i centrat.

    Ubicació: resources/views/components/guest-layout.blade.php

    Propòsit: Layout per a usuaris no autenticats (login, registre).

    <?php
<!DOCTYPE html>
<html lang="{{ str_replace('_', '-', app()->getLocale()) }}">
    <head>
        <meta charset="utf-8">
        <meta name="viewport" content="width=device-width, initial-scale=1">
        <meta name="csrf-token" content="{{ csrf_token() }}">

        <title>{{ config('app.name', 'Laravel') }}</title>

        <!-- Fonts -->
        <link rel="preconnect" href="https://fonts.bunny.net">
        <link href="https://fonts.bunny.net/css?family=figtree:400,500,600&display=swap" rel="stylesheet" />

        <!-- Scripts -->
        @vite(['resources/css/app.css', 'resources/js/app.js'])
    </head>
    <body class="font-sans text-gray-900 antialiased">
        <div class="min-h-screen flex flex-col sm:justify-center items-center pt-6 sm:pt-0 bg-gray-100">
            <div>
                <a href="/">
                    <x-application-logo class="w-20 h-20 fill-current text-gray-500" />
                </a>
            </div>

            <div class="w-full sm:max-w-md mt-6 px-6 py-4 bg-white shadow-md overflow-hidden sm:rounded-lg">
                {{ $slot }}
            </div>
        </div>
    </body>
</html>

    6.7. Quan usar cada sintaxi¶

    Triar entre sintaxi tradicional i components depén del context del teu projecte, les teues necessitats i la teua familiaritat amb cada enfocament. Ací t'ajudem a decidir.

    6.7.1. Usa sintaxi tradicional (@extends)¶

    La sintaxi tradicional és ideal per a projectes simples, equips que ja la coneixen, o quan treballes amb codi existent que usa este estil.

    Quan:

    • ✅ Crees layouts personalitzats des de zero.
    • ✅ Treballes en projectes legacy/existents.
    • ✅ Preferixes la sintaxi clàssica de Blade.
    • ✅ No necessites la complexitat de components.
    Exemple de cas d'ús: 
    <?php
{{ -- Layout simple para landing page -- }}
@extends('layouts.landing')

@section('hero')
    <h1>Bienvenido a Mi Tienda</h1>
@endsection

@section('content')
    <!-- Contenido de la landing -->
@endsection

    6.7.2. Usa sintaxi de components (<x-app-layout>)¶

    La sintaxi de components és més potent i flexible, especialment quan necessites passar dades i lògica complexa als teus layouts, o quan treballes amb paquets moderns.

    Quan:

    • ✅ Uses Laravel Breeze o Jetstream.
    • ✅ Necessites layouts amb lògica PHP complexa.
    • ✅ Vols aprofitar props i slots.
    • ✅ Treballes en projectes moderns de Laravel.
    Exemple de cas d'ús: 
    <?php
{{ -- Layout con lógica compleja -- }}
<x-app-layout :show-sidebar="true" :theme="$userTheme">
    <x-slot name="header">
        <h2>Dashboard</h2>
    </x-slot>

    <!-- Contenido principal -->

    <x-slot name="sidebar">
        <!-- Sidebar dinámico -->
    </x-slot>
</x-app-layout>
