# <img src="../../img/laravel_azul.svg" width="40"> 10.3. Proves i documentació

Una API no es dona per acabada fins que s'ha **verificat** que respon el que ha de respondre i està **documentada** perquè altres persones la puguen utilitzar. En este apartat veurem tres ferramentes:

| Ferramenta | Per a què |
| --- | --- |
| **REST Client** | Provar a mà cada petició des de VS Code. |
| **Tests de Laravel** | Comprovar automàticament que l'API continua funcionant després de cada canvi. |
| **Scribe** | Generar la documentació de l'API a partir del codi. |

## 1. Proves manuals amb REST Client

**REST Client** és una extensió de *Visual Studio Code* que permet llançar peticions HTTP escrites en un fitxer de text. També pots utilitzar *Postman*, *Insomnia* o *Thunder Client*.

Crea un fitxer **`notes.rest`** a l'arrel del projecte. Per a llançar una petició, prem **`Send Request`**, que apareix damunt de cadascuna.

```http
@base = http://testear.test/api

### Listar notas (primera página)
GET {{base}}/notes
Accept: application/json

### Segunda página
GET {{base}}/notes?page=2
Accept: application/json

### Ver la nota 1
GET {{base}}/notes/1
Accept: application/json

### Crear una nota
POST {{base}}/notes
Accept: application/json
Content-Type: application/json

{
    "title": "Nueva nota",
    "description": "Descripción de la nueva nota",
    "date_at": "2026-10-01",
    "done": false
}

### Modificar la nota 1
PUT {{base}}/notes/1
Accept: application/json
Content-Type: application/json

{
    "title": "Nota modificada",
    "description": "Descripción modificada",
    "date_at": "2026-10-02",
    "done": true
}

### Eliminar la nota 1
DELETE {{base}}/notes/1
Accept: application/json

### Error de validación (debe responder 422)
POST {{base}}/notes
Accept: application/json
Content-Type: application/json

{
    "title": ""
}

### Nota inexistente (debe responder 404)
GET {{base}}/notes/99999
Accept: application/json
```

En este fitxer cal fixar-se en:

1. **`###`** separa peticions. El text que el seguix és només un comentari.
2. **`@base`** definix una variable que s'utilitza amb `{{base}}`. Si canvia la URL del projecte, només es canvia en un lloc.
3. Totes les peticions porten **`Accept: application/json`**: és el que faria un client real i garantix respostes JSON.
4. Les peticions amb cos porten **`Content-Type: application/json`** i una **línia en blanc** entre les capçaleres i el cos.

!!!tenencuenta "Comprova el codi d'estat, no només el cos"
    A la resposta, mira la primera línia (`HTTP/1.1 201 Created`, `HTTP/1.1 422 Unprocessable Content`…). Una API pot tornar un JSON amb bona pinta i un codi incorrecte.

## 2. Proves automàtiques (tests)

Provar a mà està bé mentre es desenvolupa, però quan l'API creix ningú no repetix vint peticions després de cada canvi. Laravel inclou un sistema de tests que **llança les peticions per tu** i comprova les respostes.

### 2.1. Dades de prova amb una factory

Els tests necessiten notes. Creem una *factory* (unitat 8):

```bash
php artisan make:factory NoteFactory --model=Note
```

A `database/factories/NoteFactory.php`:

```php
public function definition(): array
{
    return [
        'title' => fake()->sentence(3),
        'description' => fake()->paragraph(),
        'date_at' => fake()->date(),
        'done' => fake()->boolean(),
    ];
}
```

El model `Note` ha d'utilitzar el trait `HasFactory`.

### 2.2. Escriure els tests

```bash
php artisan make:test NoteApiTest
```

A `tests/Feature/NoteApiTest.php`:

```php
<?php

namespace Tests\Feature;

use App\Models\Note;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Tests\TestCase;

class NoteApiTest extends TestCase
{
    use RefreshDatabase;

    public function test_lista_las_notas_paginadas(): void
    {
        Note::factory()->count(3)->create();

        $this->getJson('/api/notes')
            ->assertOk()
            ->assertJsonCount(3, 'data')
            ->assertJsonStructure(['data', 'links', 'meta']);
    }

    public function test_crea_una_nota(): void
    {
        $this->postJson('/api/notes', [
            'title' => 'Comprar pan',
            'description' => 'En la panadería de la esquina',
            'date_at' => '2026-10-01',
        ])
            ->assertCreated()
            ->assertJsonPath('data.titulo', 'Comprar pan');

        $this->assertDatabaseHas('notes', ['title' => 'Comprar pan']);
    }

    public function test_rechaza_datos_no_validos(): void
    {
        $this->postJson('/api/notes', [])
            ->assertUnprocessable()
            ->assertJsonValidationErrors(['title', 'description', 'date_at']);
    }

    public function test_devuelve_404_si_la_nota_no_existe(): void
    {
        $this->getJson('/api/notes/99999')->assertNotFound();
    }

    public function test_elimina_una_nota(): void
    {
        $note = Note::factory()->create();

        $this->deleteJson("/api/notes/{$note->id}")->assertNoContent();

        $this->assertDatabaseMissing('notes', ['id' => $note->id]);
    }
}
```

| Mètode | Què fa |
| --- | --- |
| `getJson`, `postJson`, `putJson`, `deleteJson` | Llancen la petició amb `Accept: application/json`. |
| `assertOk`, `assertCreated`, `assertNoContent`, `assertNotFound`, `assertUnprocessable` | Comproven el codi d'estat (200, 201, 204, 404, 422). |
| `assertJsonPath('data.titulo', ...)` | Comprova un valor concret del JSON. |
| `assertJsonValidationErrors([...])` | Comprova quins camps han fallat. |
| `assertDatabaseHas`, `assertDatabaseMissing` | Comproven el contingut de la base de dades. |

### 2.3. Executar els tests

```bash
php artisan test --filter=NoteApiTest
```

```text
   PASS  Tests\Feature\NoteApiTest
  ✓ lista las notas paginadas
  ✓ crea una nota
  ✓ rechaza datos no validos
  ✓ devuelve 404 si la nota no existe
  ✓ elimina una nota

  Tests:    5 passed
```

!!!tenencuenta "Els tests no toquen la teua base de dades"
    `RefreshDatabase` buida la base de dades en cada test. Per això, a `phpunit.xml`, Laravel utilitza una base de dades SQLite **en memòria** (`DB_CONNECTION=sqlite`, `DB_DATABASE=:memory:`), diferent de la de desenvolupament. Necessites l'extensió `pdo_sqlite` de PHP (Laragon i Sail ja la inclouen).

## 3. Documentar l'API amb Scribe

Qui haja de consumir l'API (l'equip de frontend, una altra empresa, tu d'ací a sis mesos) necessita saber quines rutes hi ha, quines dades accepten i què tornen. **Scribe** genera esta documentació llegint les rutes, els *Form Requests* i els comentaris del codi.

### 3.1. Instal·lació

```bash
composer require --dev knuckleswtf/scribe
php artisan vendor:publish --tag=scribe-config
```

A `config/scribe.php`, revisa com a mínim:

```php
'title' => 'API de notas',
'base_url' => env('APP_URL'),
'routes' => [
    [
        'match' => [
            'prefixes' => ['api/*'],
            // ...
        ],
        // ...
    ],
],
```

### 3.2. Descriure els mètodes

Scribe deduïx els paràmetres del cos a partir de les regles de `NoteRequest`. Amb comentaris al controlador afegim la resta:

```php
/**
 * @group Notas
 *
 * Gestión de las notas.
 */
class NoteController extends Controller
{
    /**
     * Listar notas
     *
     * Devuelve las notas paginadas, de 10 en 10 y de la más reciente a la más antigua.
     *
     * @queryParam page integer Número de página. Example: 1
     */
    public function index(): AnonymousResourceCollection
    {
        // ...
    }

    /**
     * Crear una nota
     *
     * @bodyParam title string required Título de la nota. Example: Comprar pan
     * @bodyParam done boolean Si la nota está completada. Example: false
     *
     * @response 201 scenario="Nota creada" {"data": {"id": 1, "titulo": "Comprar pan", "descripcion": "En la panadería", "fecha": "2026-10-01", "estado": "Pendiente", "creada": "2026-09-30T10:00:00+00:00"}}
     * @response 422 scenario="Datos no válidos" {"message": "The title field is required.", "errors": {"title": ["The title field is required."]}}
     */
    public function store(NoteRequest $request): JsonResponse
    {
        // ...
    }
}
```

### 3.3. Generar la documentació

```bash
php artisan scribe:generate
```

Scribe genera:

* una **pàgina web** amb la documentació i un botó *Try it out* per a provar cada petició (segons `config/scribe.php`, se servix a `http://testear.test/docs` o s'escriu a `public/docs`);
* un fitxer **OpenAPI** (`openapi.yaml`), el format estàndard per a descriure API REST;
* una **col·lecció de Postman**, preparada per a importar.

!!!tenencuenta "Torna a generar-la després de cada canvi"
    La documentació és una foto del codi en el moment d'executar `scribe:generate`. Si canvies rutes, regles o respostes, torna a executar-lo.

!!!tip "Si Scribe no és compatible amb la teua versió de Laravel"
    Comprova'n la compatibilitat abans d'instal·lar-lo. Com a alternativa, pots escriure a mà el fitxer `openapi.yaml` i visualitzar-lo a [editor.swagger.io](https://editor.swagger.io){:target="_blank"}, o documentar l'API com una col·lecció de Postman amb exemples de petició i resposta.
