# <img src="../../img/laravel_azul.svg" width="40"> Pràctica guiada: API REST de productes

### Objectiu

Aplicar tot el que s'ha vist en la unitat per a construir una **API REST de productes** completa: rutes, controlador, format d'eixida, validació, errors en JSON, autenticació amb tokens, proves i documentació.

Pots partir del projecte de les pràctiques anteriors (que ja té productes) o d'un de nou. En els exemples, el projecte està a `http://testear.test`.

---

### FASE 1: Preparar el projecte

1. Arranca els serveis (Docker amb `sail up -d`, o Nginx i MySQL a Laragon).
2. Si encara no tens rutes API, executa `php artisan install:api` i respon que sí a les migracions.
3. A `bootstrap/app.php`, configura que els errors de les rutes `api/*` es tornen sempre en JSON (apartat [10.1](501.md)).

### FASE 2: Taula i model (si no els tens)

| Camp | Tipus | Restriccions |
| --- | --- | --- |
| `id` | `id()` | Clau primària |
| `name` | `string` | Obligatori |
| `description` | `text` | Pot ser nul |
| `price` | `decimal(8,2)` | Obligatori |
| `stock` | `integer` | Obligatori, per defecte 0 |
| `created_at`, `updated_at` | `timestamps()` | Automàtics |

```bash
php artisan make:model Product -mf
```

Definix `$fillable` al model i una `ProductFactory` amb dades realistes. Ompli la taula amb uns 25 productes (amb un *seeder* o amb Tinker: `Product::factory(25)->create()`).

### FASE 3: Controlador i rutes

1. Crea el controlador amb `php artisan make:controller Api/ProductController --api --model=Product`.
2. Registra les rutes amb `Route::apiResource('products', ...)`.
3. Comprova que existixen les cinc rutes amb `php artisan route:list --path=api/products`.

### FASE 4: Format d'eixida amb `ProductResource`

Crea `ProductResource` amb esta estructura:

```json
{
    "id": 1,
    "nombre": "Camiseta",
    "descripcion": "Camiseta de algodón",
    "precio": 19.99,
    "precio_formateado": "19,99 €",
    "stock": 25,
    "disponible": true
}
```

* `precio` és un número (`(float) $this->price`), no un text.
* `disponible` és `true` si `stock > 0`.

Implementa els cinc mètodes **sense construir el JSON a mà**:

| Mètode | Resposta |
| --- | --- |
| `index` | Productes paginats de 10 en 10 (`data`, `links` i `meta`) |
| `store` | `201` + producte creat |
| `show` | `200` + producte |
| `update` | `200` + producte modificat |
| `destroy` | `204` sense cos |

**Extra**: permet filtrar amb `GET /api/products?search=camiseta` (busca a `name`) i `?available=1` (només amb `stock > 0`). Pista: `Product::query()->when($request->search, fn ($q, $s) => $q->where('name', 'like', "%{$s}%"))`.

### FASE 5: Validació amb `ProductRequest`

| Camp | Regles |
| --- | --- |
| `name` | obligatori, text, entre 3 i 255 caràcters |
| `description` | opcional, text, mínim 10 caràcters |
| `price` | obligatori, numèric, entre 0 i 9999.99 |
| `stock` | obligatori, enter, entre 0 i 10000 |

Utilitza `$request->validated()` a `store` i `update`. Els missatges d'error han d'eixir en castellà.

### FASE 6: Autenticació amb tokens

1. Afig `HasApiTokens` al model `User`.
2. Crea `TokenAuthController` amb `login` i `logout` (apartat [10.4](504.md)).
3. Deixa **públiques** les rutes de lectura (`index` i `show`) i protegix amb `auth:sanctum` les d'escriptura (`store`, `update` i `destroy`). Pista: dues crides a `apiResource`, una amb `only` i una altra amb `except`.
4. Crea un usuari de prova.

### FASE 7: Proves manuals

Crea `products.rest` amb estes peticions, totes amb `Accept: application/json`:

1. Login i guardat del token (`# @name login`).
2. Llistar productes, segona pàgina i cerca.
3. Veure un producte.
4. Crear un producte **sense token** → `401`.
5. Crear un producte amb token → `201`.
6. Crear un producte amb preu negatiu i estoc de text → `422`.
7. Modificar un producte → `200`.
8. Veure un producte que no existix → `404`.
9. Eliminar un producte → `204`.
10. Logout.

### FASE 8: Proves automàtiques

Crea `tests/Feature/ProductApiTest.php` amb, com a mínim, estos tests:

* el llistat respon `200` i té `data`, `links` i `meta`;
* crear sense autenticació respon `401`;
* crear amb `Sanctum::actingAs` respon `201` i el producte és a la base de dades;
* les dades no vàlides responen `422` amb errors a `price` i `stock`;
* un producte inexistent respon `404`;
* eliminar respon `204` i el producte ja no és a la base de dades.

Tots han de passar amb `php artisan test`.

### FASE 9: Documentació

1. Instal·la Scribe i documenta el grup *Productos*: descripció de cada mètode, paràmetres de cerca i exemples de resposta `201` i `422`.
2. Marca amb `@authenticated` els mètodes que exigixen token.
3. Genera la documentació amb `php artisan scribe:generate`.

???praclaravel "Lliurament de la pràctica"

    Lliura un **PDF** amb un títol per a cada captura i l'enllaç al repositori del projecte.

    **Captures requerides**

    1. `php artisan route:list --path=api` amb les rutes de productes i d'autenticació.
    2. El codi de `ProductResource`, `ProductRequest` i `ProductController`.
    3. A REST Client, les respostes de les peticions 1, 2, 4, 5, 6, 8 i 9 de la fase 7, amb el **codi d'estat visible**.
    4. L'eixida de `php artisan test` amb tots els tests superats.
    5. La pàgina de documentació generada per Scribe, amb el mètode *Crear producto* desplegat.

    **Es comprovarà que**

    * cada ruta respon amb el codi d'estat correcte;
    * cap resposta no es construïx a mà: el format el decidix `ProductResource`;
    * els errors (`401`, `404`, `422`) arriben sempre en JSON;
    * les rutes d'escriptura exigixen token i les de lectura no;
    * tots els tests passen;
    * la documentació descriu totes les rutes.
