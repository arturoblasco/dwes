## 1. Controlador API i rutes

### 1.1. Generar el controlador

El *flag* **`--api`** genera un controlador amb els cinc mètodes d'una API (sense `create` ni `edit`, que només servixen per a mostrar formularis HTML):

```bash
php artisan make:controller Api/NoteController --api --model=Note
```

Es crea `app/Http/Controllers/Api/NoteController.php` amb `index`, `store`, `show`, `update` i `destroy`. Com que indiquem `--model=Note`, els mètodes ja reben `Note $note` (*route model binding*).

### 1.2. Rutes

A `routes/api.php`:

```php
use App\Http\Controllers\Api\NoteController;

Route::apiResource('notes', NoteController::class);
```

`apiResource` crea les cinc rutes REST. Si només en vols algunes, utilitza `only` o `except`; per exemple, una API només de lectura:

```php
Route::apiResource('notes', NoteController::class)->only(['index', 'show']);
```

Comprova les rutes:

```bash
php artisan route:list --path=api/notes
```

## 2. Codis d'estat HTTP

Una API comunica el resultat amb el **codi d'estat**, no només amb el cos:

| Codi | Nom | Quan s'utilitza |
| --- | --- | --- |
| `200 OK` | Èxit | Lectura o modificació correcta que torna dades |
| `201 Created` | Creat | S'ha creat un recurs (`POST`) |
| `204 No Content` | Sense contingut | Èxit sense cos de resposta (típic de `DELETE`) |
| `401 Unauthorized` | No autenticat | Falta el token o la sessió, o no són vàlids |
| `403 Forbidden` | Prohibit | Autenticat, però sense permís per a eixa acció |
| `404 Not Found` | No trobat | El recurs no existix |
| `422 Unprocessable Content` | Dades no vàlides | Ha fallat la validació |
| `500 Internal Server Error` | Error del servidor | Error inesperat |

## 3. API Resources: controlar el JSON d'eixida

Tornar directament el model (`return $note;`) exposa **totes** les seues columnes amb els noms interns. Un **API Resource** decidix quins camps ixen i amb quin format. Així el JSON (el *contracte* amb el client) no canvia encara que canvie la base de dades.

```bash
php artisan make:resource NoteResource
```

A `app/Http/Resources/NoteResource.php`:

```php
public function toArray(Request $request): array
{
    return [
        'id' => $this->id,
        'titulo' => $this->title,
        'descripcion' => $this->description,
        'fecha' => $this->date_at->format('Y-m-d'),
        'estado' => $this->done ? 'Completada' : 'Pendiente',
        'creada' => $this->created_at->toIso8601String(),
    ];
}
```

!!!tenencuenta "`date_at` ha de ser una data"
    `$this->date_at->format(...)` només funciona si el model convertix `date_at` en data amb `casts()` (`'date_at' => 'date'`), com en el model del principi de l'apartat.

Un Resource **ja embolcalla** la resposta en una clau `data`, així que no cal construir el JSON a mà amb `response()->json([...])`:

| Al controlador | Resposta |
| --- | --- |
| `return new NoteResource($note);` | `{ "data": { "id": 5, ... } }` amb `200` |
| `return NoteResource::collection(Note::all());` | `{ "data": [ ... ] }` amb `200` |
| `return NoteResource::collection(Note::paginate(10));` | `{ "data": [...], "links": {...}, "meta": {...} }` amb `200` |

!!!teolaravel "Paginació de franc"
    Si passes un paginador a `collection()`, la resposta inclou `links` (primera pàgina, anterior, següent i última) i `meta` (pàgina actual, total, elements per pàgina…). El client demana altres pàgines amb `?page=2`.
    ```json
    {
        "data": [ { "id": 1, "titulo": "..." } ],
        "links": { "first": ".../api/notes?page=1", "next": ".../api/notes?page=2", ... },
        "meta": { "current_page": 1, "per_page": 10, "total": 23, ... }
    }
    ```

Si necessites afegir informació al costat de `data` (per exemple, un missatge), utilitza `additional`:

```php
return (new NoteResource($note))->additional(['message' => 'Nota creada correctamente.']);
```

## 4. Validació amb Form Requests

Igual que amb els formularis web, les dades que arriben a l'API es validen **abans** de guardar-les.

```bash
php artisan make:request NoteRequest
```

!!!tip "Si ja tens un `NoteRequest`"
    Si en una pràctica anterior vas crear un `NoteRequest` per a formularis Blade, el pots reutilitzar: les regles són les mateixes. Laravel ja sap respondre en JSON quan la petició ve de l'API.

A `app/Http/Requests/NoteRequest.php`:

```php
public function authorize(): bool
{
    return true;
}

public function rules(): array
{
    return [
        'title' => ['required', 'string', 'max:255'],
        'description' => ['required', 'string'],
        'date_at' => ['required', 'date'],
        'done' => ['sometimes', 'boolean'],
    ];
}
```

Si la validació falla, Laravel respon automàticament amb **`422`** i els errors per camp (gràcies a la configuració de l'apartat 10.1, encara que el client no envie `Accept: application/json`):

```json
{
    "message": "The title field is required. (and 1 more error)",
    "errors": {
        "title": ["The title field is required."],
        "date_at": ["The date at field is required."]
    }
}
```

!!!tenencuenta "Missatges en castellà"
    Perquè els missatges de validació isquen en castellà, seguix l'apartat *5.7* de [9.2. Sistema de validació](../ul04/402.md). Funciona igual per a formularis i per a l'API.

!!!tenencuenta "Accents escapats (`ó`)"
    A la resposta veuràs els accents com a `ó`. És JSON vàlid: qualsevol client (navegador, Vue, Postman) el descodifica i mostra «ó». No cal canviar res.

### 4.1. `validated()` en lloc d'`all()`

Al controlador utilitzarem **`$request->validated()`**, que torna **només** els camps que tenen regla de validació. Si un client envia camps de més (per exemple `"role": "admin"`), es descarten:

```php
$request->all();
// ['title' => '...', 'description' => '...', 'date_at' => '...', 'role' => 'admin']

$request->validated();
// ['title' => '...', 'description' => '...', 'date_at' => '...']
```

`$fillable` al model ja protegix de l'assignació massiva, però `validated()` afig una segona barrera i deixa clar quines dades s'accepten.

## 5. El controlador complet

```php
<?php

namespace App\Http\Controllers\Api;

use App\Http\Controllers\Controller;
use App\Http\Requests\NoteRequest;
use App\Http\Resources\NoteResource;
use App\Models\Note;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Resources\Json\AnonymousResourceCollection;
use Illuminate\Http\Response;

class NoteController extends Controller
{
    public function index(): AnonymousResourceCollection
    {
        return NoteResource::collection(Note::latest()->paginate(10));
    }

    public function store(NoteRequest $request): JsonResponse
    {
        $note = Note::create($request->validated());

        return (new NoteResource($note))
            ->response()
            ->setStatusCode(201);
    }

    public function show(Note $note): NoteResource
    {
        return new NoteResource($note);
    }

    public function update(NoteRequest $request, Note $note): NoteResource
    {
        $note->update($request->validated());

        return new NoteResource($note);
    }

    public function destroy(Note $note): Response
    {
        $note->delete();

        return response()->noContent();
    }
}
```

Fixa't que:

* `show`, `update` i `destroy` reben `Note $note`. Si l'ID no existix, Laravel respon **`404`** abans d'entrar al mètode: no cal `findOrFail` ni `try`/`catch`.
* `store` respon **`201`** i `destroy` respon **`204`** sense cos.
* Cap mètode construïx el JSON a mà: el format el decidix `NoteResource`.

| Mètode | Resposta correcta | Respostes d'error possibles |
| --- | --- | --- |
| `index` | `200` + llista paginada | — |
| `store` | `201` + nota creada | `422` |
| `show` | `200` + nota | `404` |
| `update` | `200` + nota modificada | `404`, `422` |
| `destroy` | `204` | `404` |

En l'apartat següent comprovarem totes estes respostes.
