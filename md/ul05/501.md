## 1. Activar el sistema de rutas API

Desde **Laravel 11**, el archivo `routes/api.php` **no viene incluido por defecto**: la aplicación es más ligera si no vas a construir una API. Para activarlo:

```bash
php artisan install:api
```

Este comando:

* Crea el archivo `routes/api.php` y lo registra en `bootstrap/app.php`.
* Aplica a esas rutas el grupo de middleware `api` y el prefijo `/api`.
* Instala **Laravel Sanctum** (lo usaremos en el apartado 10.4 para la autenticación) y publica la migración de la tabla `personal_access_tokens`. Al final pregunta si quieres ejecutar las migraciones: puedes responder que sí.

## 2. ¿Dónde se registra esta configuración?

Desde Laravel 11 ya no existe `RouteServiceProvider`: los archivos de rutas se registran en **`bootstrap/app.php`**. Después de `install:api` verás algo así:

```php hl_lines="4"
->withRouting(
    web: __DIR__.'/../routes/web.php',
    api: __DIR__.'/../routes/api.php',
    commands: __DIR__.'/../routes/console.php',
    health: '/up',
)
```

El prefijo por defecto es `api`. Si quieres cambiarlo (por ejemplo, para versionar la API), añade la clave `apiPrefix`:

```php
->withRouting(
    api: __DIR__.'/../routes/api.php',
    apiPrefix: 'api/v1',
    // ...
)
```

## 3. `web.php` y `api.php`

| Archivo | Propósito | Middleware |
| --- | --- | --- |
| `routes/web.php` | Rutas que devuelven vistas HTML | `web`: sesión, cookies, protección CSRF |
| `routes/api.php` | Rutas que devuelven JSON | `api`: sin sesión ni CSRF, pensado para peticiones *stateless* |

!!!examplelaravel "Ejemplo del prefijo automático"
    En `routes/api.php`:
    ```php
    Route::get('/notes', function () {
        return ['mensaje' => 'Esta es la API de notas'];
    });
    ```

    Accediendo a `http://testear.test/api/notes` se obtiene `{ "mensaje": "Esta es la API de notas" }`. Laravel convierte automáticamente los arrays devueltos en JSON.

En `api.php` **no** se escribe `/api` en la ruta (Laravel lo añade), pero el cliente **sí** debe incluirlo en la URL de la petición.

## 4. Que los errores también sean JSON

Un cliente de una API espera JSON **siempre**, también cuando algo falla. Laravel decide el formato de los errores (validación, 404, 403…) según lo que pide el cliente:

* si la petición lleva la cabecera **`Accept: application/json`**, responde en JSON;
* si no la lleva, responde como a un navegador: con una página HTML de error o, si falla la validación, con una **redirección `302`** al formulario anterior.

Este es el error más habitual al empezar: una petición de prueba sin `Accept: application/json` que, en lugar de un `422` con los errores, recibe un `302`.

Para que la API responda **siempre** en JSON, aunque el cliente olvide la cabecera, se configura en `bootstrap/app.php`:

```php
use Illuminate\Http\Request;

->withExceptions(function (Exceptions $exceptions) {
    $exceptions->shouldRenderJsonWhen(function (Request $request, Throwable $e) {
        return $request->is('api/*') || $request->expectsJson();
    });
})
```

Con esto, cualquier ruta que empiece por `/api` devolverá sus errores en JSON con el código adecuado:

| Situación | Código | Cuerpo |
| --- | --- | --- |
| Falla la validación | `422` | `{ "message": "...", "errors": { "campo": ["..."] } }` |
| El recurso no existe | `404` | `{ "message": "..." }` |
| No autenticado | `401` | `{ "message": "Unauthenticated." }` |
| Sin permiso | `403` | `{ "message": "This action is unauthorized." }` |

!!!tenencuenta "Mensaje propio para el 404"
    El mensaje por defecto de un 404 incluye el nombre del modelo (`No query results for model [App\\Models\\Note] 9`). Si prefieres un mensaje propio para la API, añade en el mismo `withExceptions`:
    ```php
    use Symfony\Component\HttpKernel\Exception\NotFoundHttpException;

    $exceptions->render(function (NotFoundHttpException $e, Request $request) {
        if ($request->is('api/*')) {
            return response()->json(['message' => 'Recurso no encontrado.'], 404);
        }
    });
    ```

Así **no hace falta** capturar excepciones con `try`/`catch` en cada método del controlador: el manejador de excepciones de Laravel se encarga de todos a la vez.
