# <img src="../../img/laravel_azul.svg" width="40"> 10.0. Introducció

Fins ara, les nostres aplicacions Laravel tornaven **pàgines HTML** generades amb Blade. En esta unitat el backend canvia de paper: deixa de pintar pantalles i passa a oferir un **servei web** que torna **dades en JSON**. Qualsevol client (una SPA en Vue, una aplicació mòbil, un altre servidor) pot consumir eixes dades.

> *"Utilitzem un backend amb API perquè l'aplicació no depenga de com es veu,
> sinó de com funciona, i poder utilitzar les dades des de qualsevol lloc."*

## 1. Què és una API REST que torna JSON?

És un backend que:

- rep peticions HTTP (`GET`, `POST`, `PUT`/`PATCH`, `DELETE`) sobre **recursos** identificats per URL (`/api/notes`, `/api/notes/5`);
- processa les dades (base de dades, regles de negoci, permisos);
- respon amb **JSON** i amb un **codi d'estat HTTP** que indica què ha passat.

```json
{
    "data": {
        "id": 5,
        "titulo": "Comprar pan",
        "estado": "Pendiente"
    }
}
```

## 2. Per a què servix?

| Avantatge | En la pràctica |
| --- | --- |
| **Separar frontend i backend** | El backend gestiona dades, regles i seguretat. El frontend només mostra. Es pot canviar l'un sense tocar l'altre. |
| **Reutilitzar el backend** | La mateixa API servix una web en Vue, una aplicació mòbil o un altre sistema. |
| **Comunicació estàndard** | HTTP + JSON: qualsevol llenguatge el sap llegir. |
| **Treball en equip** | Qui fa l'API i qui fa el frontend avancen en paral·lel si acorden el *contracte* (rutes, JSON i errors). |
| **Seguretat** | El client mai no accedix a la base de dades: només a allò que l'API decidix exposar. |

| Sense API (tot junt) | Amb API JSON |
| --- | --- |
| HTML i PHP mesclats | Frontend i backend separats |
| Poc reutilitzable | Molt reutilitzable |
| Difícil d'escalar | Escalable |
| Acoblat | Modular |

## 3. REST en quatre regles

1. **Recursos amb nom**: les URL anomenen coses, no accions (`/api/notes`, no `/api/getNotes`).
2. **El mètode HTTP indica l'acció**: `GET` llig, `POST` crea, `PUT`/`PATCH` modifica i `DELETE` elimina.
3. **Sense estat (*stateless*)**: cada petició porta tot el que cal (per exemple, el token). El servidor no recorda la petició anterior.
4. **Codis d'estat amb significat**: `200`, `201`, `204`, `401`, `403`, `404`, `422`… (es detallen en l'apartat 10.2).
