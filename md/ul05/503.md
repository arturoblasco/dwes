# <img src="../../img/laravel_azul.svg" width="40"> 10.3. Pruebas y documentación

Una API no se da por terminada hasta que se ha **verificado** que responde lo que debe y está **documentada** para que otras personas puedan usarla. En este apartado veremos tres herramientas:

| Herramienta | Para qué |
| --- | --- |
| **REST Client** | Probar a mano cada petición desde VS Code. |
| **Tests de Laravel** | Comprobar automáticamente que la API sigue funcionando después de cada cambio. |
| **Scribe** | Generar la documentación de la API a partir del código. |

## 1. Pruebas manuales con REST Client

**REST Client** es una extensión de *Visual Studio Code* que permite lanzar peticiones HTTP escritas en un archivo de texto. También puedes usar *Postman*, *Insomnia* o *Thunder Client*.

Crea un archivo **`notes.rest`** en la raíz del proyecto. Para lanzar una petición, pulsa **`Send Request`**, que aparece encima de cada una.

```http
@base = http://testear.test/api

### Listar notas (primera página)
GET {{base}}/notes
Accept: application/json

### Segunda página
GET {{base}}/notes?page=2
Accept: application/json

### Ver la nota 1
GET {{base}}/notes/1
Accept: application/json

### Crear una nota
POST {{base}}/notes
Accept: application/json
Content-Type: application/json

{
    "title": "Nueva nota",
    "description": "Descripción de la nueva nota",
    "date_at": "2026-10-01",
    "done": false
}

### Modificar la nota 1
PUT {{base}}/notes/1
Accept: application/json
Content-Type: application/json

{
    "title": "Nota modificada",
    "description": "Descripción modificada",
    "date_at": "2026-10-02",
    "done": true
}

### Eliminar la nota 1
DELETE {{base}}/notes/1
Accept: application/json

### Error de validación (debe responder 422)
POST {{base}}/notes
Accept: application/json
Content-Type: application/json

{
    "title": ""
}

### Nota inexistente (debe responder 404)
GET {{base}}/notes/99999
Accept: application/json
```

En este archivo hay que fijarse en:

1. **`###`** separa peticiones. El texto que lo sigue es solo un comentario.
2. **`@base`** define una variable que se usa con `{{base}}`. Si cambia la URL del proyecto, solo se cambia en un sitio.
3. Todas las peticiones llevan **`Accept: application/json`**: es lo que haría un cliente real y garantiza respuestas JSON.
4. Las peticiones con cuerpo llevan **`Content-Type: application/json`** y una **línea en blanco** entre las cabeceras y el cuerpo.

!!!tenencuenta "Comprueba el código de estado, no solo el cuerpo"
    En la respuesta, mira la primera línea (`HTTP/1.1 201 Created`, `HTTP/1.1 422 Unprocessable Content`…). Una API puede devolver un JSON con buena pinta y un código incorrecto.

## 2. Pruebas automáticas (tests)

Probar a mano está bien mientras se desarrolla, pero cuando la API crece nadie repite veinte peticiones después de cada cambio. Laravel incluye un sistema de tests que **lanza las peticiones por ti** y comprueba las respuestas.

### 2.1. Datos de prueba con una factory

Los tests necesitan notas. Creamos una *factory* (unidad 8):

```bash
php artisan make:factory NoteFactory --model=Note
```

En `database/factories/NoteFactory.php`:

```php
public function definition(): array
{
    return [
        'title' => fake()->sentence(3),
        'description' => fake()->paragraph(),
        'date_at' => fake()->date(),
        'done' => fake()->boolean(),
    ];
}
```

El modelo `Note` debe usar el trait `HasFactory`.

### 2.2. Escribir los tests

```bash
php artisan make:test NoteApiTest
```

En `tests/Feature/NoteApiTest.php`:

```php
<?php

namespace Tests\Feature;

use App\Models\Note;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Tests\TestCase;

class NoteApiTest extends TestCase
{
    use RefreshDatabase;

    public function test_lista_las_notas_paginadas(): void
    {
        Note::factory()->count(3)->create();

        $this->getJson('/api/notes')
            ->assertOk()
            ->assertJsonCount(3, 'data')
            ->assertJsonStructure(['data', 'links', 'meta']);
    }

    public function test_crea_una_nota(): void
    {
        $this->postJson('/api/notes', [
            'title' => 'Comprar pan',
            'description' => 'En la panadería de la esquina',
            'date_at' => '2026-10-01',
        ])
            ->assertCreated()
            ->assertJsonPath('data.titulo', 'Comprar pan');

        $this->assertDatabaseHas('notes', ['title' => 'Comprar pan']);
    }

    public function test_rechaza_datos_no_validos(): void
    {
        $this->postJson('/api/notes', [])
            ->assertUnprocessable()
            ->assertJsonValidationErrors(['title', 'description', 'date_at']);
    }

    public function test_devuelve_404_si_la_nota_no_existe(): void
    {
        $this->getJson('/api/notes/99999')->assertNotFound();
    }

    public function test_elimina_una_nota(): void
    {
        $note = Note::factory()->create();

        $this->deleteJson("/api/notes/{$note->id}")->assertNoContent();

        $this->assertDatabaseMissing('notes', ['id' => $note->id]);
    }
}
```

| Método | Qué hace |
| --- | --- |
| `getJson`, `postJson`, `putJson`, `deleteJson` | Lanzan la petición con `Accept: application/json`. |
| `assertOk`, `assertCreated`, `assertNoContent`, `assertNotFound`, `assertUnprocessable` | Comprueban el código de estado (200, 201, 204, 404, 422). |
| `assertJsonPath('data.titulo', ...)` | Comprueba un valor concreto del JSON. |
| `assertJsonValidationErrors([...])` | Comprueba qué campos han fallado. |
| `assertDatabaseHas`, `assertDatabaseMissing` | Comprueban el contenido de la base de datos. |

### 2.3. Ejecutar los tests

```bash
php artisan test --filter=NoteApiTest
```

```text
   PASS  Tests\Feature\NoteApiTest
  ✓ lista las notas paginadas
  ✓ crea una nota
  ✓ rechaza datos no validos
  ✓ devuelve 404 si la nota no existe
  ✓ elimina una nota

  Tests:    5 passed
```

!!!tenencuenta "Los tests no tocan tu base de datos"
    `RefreshDatabase` vacía la base de datos en cada test. Por eso, en `phpunit.xml`, Laravel usa una base de datos SQLite **en memoria** (`DB_CONNECTION=sqlite`, `DB_DATABASE=:memory:`), distinta de la de desarrollo. Necesitas la extensión `pdo_sqlite` de PHP (Laragon y Sail ya la incluyen).

## 3. Documentar la API con Scribe

Quien vaya a consumir la API (el equipo de frontend, otra empresa, tú dentro de seis meses) necesita saber qué rutas hay, qué datos aceptan y qué devuelven. **Scribe** genera esta documentación leyendo las rutas, los *Form Requests* y los comentarios del código.

### 3.1. Instalación

```bash
composer require --dev knuckleswtf/scribe
php artisan vendor:publish --tag=scribe-config
```

En `config/scribe.php`, revisa al menos:

```php
'title' => 'API de notas',
'base_url' => env('APP_URL'),
'routes' => [
    [
        'match' => [
            'prefixes' => ['api/*'],
            // ...
        ],
        // ...
    ],
],
```

### 3.2. Describir los métodos

Scribe deduce los parámetros del cuerpo a partir de las reglas de `NoteRequest`. Con comentarios en el controlador añadimos el resto:

```php
/**
 * @group Notas
 *
 * Gestión de las notas.
 */
class NoteController extends Controller
{
    /**
     * Listar notas
     *
     * Devuelve las notas paginadas, de 10 en 10 y de la más reciente a la más antigua.
     *
     * @queryParam page integer Número de página. Example: 1
     */
    public function index(): AnonymousResourceCollection
    {
        // ...
    }

    /**
     * Crear una nota
     *
     * @bodyParam title string required Título de la nota. Example: Comprar pan
     * @bodyParam done boolean Si la nota está completada. Example: false
     *
     * @response 201 scenario="Nota creada" {"data": {"id": 1, "titulo": "Comprar pan", "descripcion": "En la panadería", "fecha": "2026-10-01", "estado": "Pendiente", "creada": "2026-09-30T10:00:00+00:00"}}
     * @response 422 scenario="Datos no válidos" {"message": "The title field is required.", "errors": {"title": ["The title field is required."]}}
     */
    public function store(NoteRequest $request): JsonResponse
    {
        // ...
    }
}
```

### 3.3. Generar la documentación

```bash
php artisan scribe:generate
```

Scribe genera:

* una **página web** con la documentación y un botón *Try it out* para probar cada petición (según `config/scribe.php`, se sirve en `http://testear.test/docs` o se escribe en `public/docs`);
* un archivo **OpenAPI** (`openapi.yaml`), el formato estándar para describir APIs REST;
* una **colección de Postman**, lista para importar.

!!!tenencuenta "Vuelve a generarla después de cada cambio"
    La documentación es una foto del código en el momento de ejecutar `scribe:generate`. Si cambias rutas, reglas o respuestas, vuelve a ejecutarlo.

!!!tip "Si Scribe no es compatible con tu versión de Laravel"
    Comprueba la compatibilidad antes de instalarlo. Como alternativa, puedes escribir a mano el archivo `openapi.yaml` y visualizarlo en [editor.swagger.io](https://editor.swagger.io){:target="_blank"}, o documentar la API como una colección de Postman con ejemplos de petición y respuesta.
