# <img src="../../img/laravel_azul.svg" width="40"> Pràctica guiada: notes amb Laravel i Vue

### Objectiu

Construir una aplicació híbrida completa: una **API Laravel** protegida amb **Sanctum en mode SPA** i un **frontend Vue** que la consumix, amb:

* login, sessió que es manté en recarregar i logout;
* llistat paginat, creació i esborrat de notes;
* errors de validació mostrats al formulari;
* cada usuari només gestiona les seues notes, i un administrador pot fer-ho amb totes.

Partix del projecte `testear` de la unitat 10 (API de notes amb tokens). Si ho preferixes, pots aplicar la pràctica als **productes** de la pràctica guiada de la unitat 10.

---

### Part A. Backend (Laravel)

1. **Sessió per a la SPA**: afig `$middleware->statefulApi()` a `bootstrap/app.php`.
2. **Dominis de confiança**: a `.env`, `SANCTUM_STATEFUL_DOMAINS=localhost:5173` i `SESSION_DOMAIN=null`. Executa `php artisan config:clear`.
3. **Login i logout**: crea `SpaAuthController` amb `login` i `logout` (apartat [11.1](701.md)) i les seues rutes `POST /api/login` (amb `throttle:6,1`) i `POST /api/logout` (amb `auth:sanctum`).
4. **Rutes protegides**: `GET /api/user` i `apiResource('notes')` dins del grup `auth:sanctum`.
5. **Propietaris i rols**: migracions `user_id` a `notes` i `role` a `users`, i relacions `User::notes()` i `Note::user()`.
6. **Policy**: `NotePolicy` amb `before` per a l'administrador i les regles `view`, `update` i `delete`.
7. **Controlador**: `index` filtra per usuari, `store` crea la nota a nom de l'usuari autenticat, i `show`, `update` i `destroy` criden `Gate::authorize`.
8. **Resource**: afig a `NoteResource` el camp `permisos` (`editar` i `borrar`).
9. **Usuaris de prova**: dos usuaris normals i un administrador (amb un *seeder* o amb Tinker).

### Part B. Frontend (Vue)

10. Crea el projecte amb `npm create vite@latest notas-vue -- --template vue` i instal·la axios.
11. Configura el **proxy** de `/api` i `/sanctum` a `vite.config.js` (apartat [11.2](702.md)).
12. Crea `src/services/api.js` amb `Accept: application/json`, `withCredentials` i `withXSRFToken`.
13. Crea `src/services/auth.js` (`login`, `logout`, `currentUser`) i `src/services/notes.js` (`fetchNotes`, `createNote`, `deleteNote`).
14. Crea els components:
    * `LoginForm.vue`: formulari amb l'error de credencials davall del correu.
    * `NotesPanel.vue`: formulari de nota nova amb els errors per camp, llista amb paginació i botó **Borrar** només si `note.permisos.borrar`.
    * `App.vue`: comprova la sessió en arrancar i mostra el login o el tauler, amb el nom de l'usuari i el botó **Salir**.
15. Tracta els errors per codi: `401` torna al login, `403` avisa i `422` mostra els errors al formulari.

**Extra**: afig l'edició de notes (`PUT /api/notes/{id}`) amb el botó **Editar** controlat per `note.permisos.editar`, i un filtre *pendents/completades*.

### Part C. Comprovacions

| Comprovació | Resultat esperat |
| --- | --- |
| Login amb credencials correctes | `200` i apareix el tauler |
| Login amb contrasenya incorrecta | `422` i el missatge davall del correu |
| Recarregar la pàgina després del login | Continues autenticat |
| Crear una nota sense títol | `422` i l'error davall del camp |
| Usuari A | Només veu les seues notes |
| Administrador | Veu les notes de tots i les pot esborrar |
| REST Client amb el token de B: `DELETE` d'una nota d'A | `403` |
| Eixir i després `GET /api/user` | `401` i torna el login |

### Preguntes de reflexió

1. Per què cal cridar `/sanctum/csrf-cookie` abans del login? Quin error apareix si no es fa?
2. Per què el login funciona amb el proxy de Vite i deixa de funcionar si axios crida directament `http://testear.test`?
3. Quines diferències hi ha entre un token Bearer i una galeta de sessió en seguretat i en comoditat? Quan utilitzaries cadascun?
4. Si Vue ja amaga el botó **Borrar** quan no hi ha permís, per què cal `Gate::authorize` al controlador?
5. Quin avantatge té que l'API envie el camp `permisos` en lloc de repetir les regles en Vue?
