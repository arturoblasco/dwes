# <img src="../../img/laravel_azul.svg" width="40"> 11.0. Introducció

En la unitat 10 vam construir una API REST de notes. En esta unitat la consumirem des d'un **frontend en Vue**: una aplicació d'una sola pàgina (**SPA**) que s'executa al navegador, demana les dades a l'API i pinta la interfície. El resultat és una **aplicació web híbrida**: Laravel al servidor i Vue al client.

## 1. Arquitectura

```text
[ Navegador: SPA en Vue ]  ── HTTP (axios) ──>  [ API Laravel ]  ──>  [ Base de dades ]
   pinta pantalles,                               valida, aplica regles
   formularis, botons                             i permisos, consulta la BD
                          <──── JSON ────────
```

> **Idea clau**: Vue no parla amb la base de dades. Vue parla amb l'API, i l'API parla amb la base de dades.

| Part | Responsabilitat | Tecnologia |
| --- | --- | --- |
| **Backend** (DWES) | Dades, validació, autenticació, permisos | Laravel + Sanctum |
| **Frontend** (DWEC) | Interfície, navegació, experiència d'usuari | Vue + Vite + axios |
| **Contracte** | Rutes, format JSON i codis d'error | Documentació de l'API (apartat 10.3) |

Si el contracte no canvia, cada part pot evolucionar sense trencar l'altra. És la base d'un **projecte intermodular**: en DWES es desenvolupa l'API i en DWEC es consumix.

## 2. Un exemple mínim

**Backend**: la ruta `GET /api/notes` de la unitat 10 (sense autenticació, com al final de l'apartat 10.2) torna:

```json
{
    "data": [
        { "id": 1, "titulo": "Comprar pan", "estado": "Pendiente" },
        { "id": 2, "titulo": "Estudiar Vue", "estado": "Completada" }
    ]
}
```

**Frontend**: un component Vue la consumix i pinta la llista.

```vue
<script setup>
import { ref, onMounted } from "vue";
import axios from "axios";

const notes = ref([]);
const loading = ref(true);
const error = ref("");

onMounted(async () => {
    try {
        const res = await axios.get("/api/notes", { headers: { Accept: "application/json" } });
        notes.value = res.data.data;
    } catch (e) {
        error.value = "No se han podido cargar las notas.";
    } finally {
        loading.value = false;
    }
});
</script>

<template>
    <p v-if="loading">Cargando…</p>
    <p v-else-if="error">{{ error }}</p>
    <ul v-else>
        <li v-for="note in notes" :key="note.id">{{ note.titulo }} ({{ note.estado }})</li>
    </ul>
</template>
```

Si la base de dades canvia, o si s'afigen regles o permisos, Vue no se n'assabenta mentre el JSON continue sent el mateix. I una aplicació mòbil podria utilitzar exactament la mateixa API.

## 3. Com s'autentica una SPA?

En l'apartat 10.4 vam utilitzar **tokens Bearer**. Funcionen des d'una SPA, però obliguen a guardar el token en JavaScript (`localStorage` o memòria):

| | Token Bearer | Galeta de sessió (Sanctum SPA) |
| --- | --- | --- |
| On es guarda | En JavaScript (`localStorage`, memòria) | En una galeta **HttpOnly** que JavaScript no pot llegir |
| Risc si hi ha XSS | Un script maliciós pot robar el token | L'script no pot llegir la galeta |
| Enviament en cada petició | Cal afegir la capçalera `Authorization` | El navegador envia la galeta automàticament |
| Protecció CSRF | No cal | Sí: galeta `XSRF-TOKEN` + capçalera `X-XSRF-TOKEN` |
| Ideal per a | Postman, aplicacions mòbils, servidors | SPA al navegador **en el mateix domini** que l'API |

Per a una SPA al navegador, Sanctum recomana el seu **mode SPA**: autenticació amb la **sessió de Laravel** a través de galetes.
