# <img src="../../img/laravel_azul.svg" width="40"> 9.7. Sistema d'emmagatzematge de fitxers

En les sessions anteriors vas aprendre a gestionar formularis, validar dades i autenticar usuaris. Però què passa quan els usuaris pugen **fitxers** com ara imatges de perfil, fotos de productes o documents?

L'emmagatzematge de fitxers és una necessitat fonamental en aplicacions web modernes. Laravel proporciona un sistema d'emmagatzematge robust, segur i fàcil d'usar a través de la seua facade `Storage`.

## 7.1. Per què necessitem un sistema d'emmagatzematge?

Quan els usuaris pugen fitxers a la teua aplicació (imatges, documents, vídeos), estos fitxers han de:

1. **Emmagatzemar-se en el servidor** de forma segura.
2. **Ser accessibles** públicament (per a imatges que es mostren en la web).
3. **Gestionar-se** (crear, llegir, actualitzar, eliminar).
4. **Organitzar-se** en directoris lògics.

## 7.2. Discos d'emmagatzematge en Laravel

Laravel organitza l'emmagatzematge en "discos" (disks), que són ubicacions configurades on es guarden fitxers.

### 7.2.1. Discos predefinits

Laravel ve amb tres discos configurats per defecte, cadascun amb un propòsit específic segons el nivell d'accés i la ubicació requerida.

| Disc | Ubicació | Accés Públic | Ús Típic |
| --- | --- | --- | --- |
| **local** | `storage/app/` | ❌ No | Fitxers privats, logs interns |
| **public** | `storage/app/public/` | ✅ Sí (amb enllaç simbòlic) | Imatges de productes, avatars |
| **s3** | Amazon S3 (núvol) | ✅ Configurable | Fitxers en producció, alta escalabilitat |

### 7.2.2. Configuració de discos

Els discos es configuren en **`config/filesystems.php`**:

```php
<?php

return [
    'default' => env('FILESYSTEM_DISK', 'local'),

    'disks' => [
        'local' => [
            'driver' => 'local',
            'root' => storage_path('app'),
            'throw' => false,
        ],

        'public' => [
            'driver' => 'local',
            'root' => storage_path('app/public'),
            'url' => env('APP_URL').'/storage',
            'visibility' => 'public',
            'throw' => false,
        ],

        's3' => [
            'driver' => 's3',
            'key' => env('AWS_ACCESS_KEY_ID'),
            'secret' => env('AWS_SECRET_ACCESS_KEY'),
            'region' => env('AWS_DEFAULT_REGION'),
            'bucket' => env('AWS_BUCKET'),
            'url' => env('AWS_URL'),
        ],
    ],
];
```

## 7.3. El disc públic i l'enllaç simbòlic

El disc `public` és especial perquè ha de ser accessible des de la web, però per defecte està en `storage/app/public/`, que **no és accessible públicament**.

### 7.3.1. Per què existix este problema?

La carpeta **`storage/`** està fora de la carpeta **`public/`** per seguretat. Els navegadors només poden accedir a fitxers dins de `public/`, per la qual cosa els fitxers en **`storage/app/public/` no són accessibles directament**.

```text
tu-proyecto/
├── public/              ←  Carpeta accesible por navegadores (www.tuapp.com/)
│   ├── index.php
│   ├── css/
│   └── js/
└── storage/             ←  Carpeta PRIVADA, NO accesible por navegadores
    └── app/
        └── public/      ←← ¿Cómo hacer que esto sea accesible?
            └── products/
                └── iphone.jpg
```

**Problema:**

* Els navegadors només poden accedir a fitxers en `public/`
* Però guardem fitxers en `storage/app/public/`
* Els navegadors **no poden** accedir directament a `storage/`

### 7.3.2. Solució: enllaç simbòlic

Un **enllaç simbòlic** (*symbolic link*) és com un "portal" que connecta dues ubicacions:

```bash
# Crear el enlace simbólico
php artisan storage:link
```

**Resultat:**

```text
public/storage → storage/app/public/
   (enlace)        (carpeta real)
```

Ara:

```text
www.tuapp.com/storage/products/iphone.jpg

              ↓

public/storage/products/iphone.jpg

              ↓ (enlace simbólico)

storage/app/public/products/iphone.jpg
```

!!!tenencuenta "Quan crear l'enllaç simbòlic"
    Sempre has d'executar **`php artisan storage:link`** després de:

    * Clonar el projecte per primera vegada.
    * Configurar un nou entorn de desenvolupament.
    * Desplegar en un nou servidor.
    
    **Sense l'enllaç simbòlic, les imatges no es mostraran en el navegador.**

### 7.3.3. Verificar l'enllaç

Pots verificar si l'enllaç simbòlic ja existix executant el comandament novament. Si existix, Laravel t'ho indicarà per a evitar conflictes.

```bash
# Verificar si el enlace existe
sail artisan storage:link

# Si ya existe, verás:
# The "public/storage" directory already exists.

# Para forzar la recreación:
sail artisan storage:link --force
```

## 7.4. Operacions bàsiques amb Storage

La facade **`Storage`** proporciona mètodes simples per a guardar, llegir, actualitzar i eliminar fitxers. Estes operacions són consistents independentment del disc que uses (`local`, `public`, `s3`).

### 7.4.1. Guardar fitxers

Per a guardar fitxers des d'un formulari, usa el mètode **`store()`** o **`storeAs()`** del fitxer pujat. Laravel gestiona automàticament el nom i la ubicació del fitxer.

**Des d'un formulari:**

```php
<?php

namespace App\Http\Controllers;

use Illuminate\Http\Request;
use Illuminate\Support\Facades\Storage;

class ProductController extends Controller
{
    public function store(Request $request)
    {
        // Validar el archivo
        $request->validate([
            'image' => 'required|image|mimes:jpeg,png,jpg,gif|max:2048', // 2MB máximo
        ]);

        // Guardar el archivo en storage/app/public/products/
        $path = $request->file('image')->store('products', 'public');
        // $path: contiene la ruta relativa (products/abc123def456.jpg>)
        
        // Guardar la ruta en la base de datos
        $product = Product::create([
            'name' => $request->name,
            'image' => $path,  // ← Guardamos la ruta
        ]);

        return redirect()->route('products.show', $product);
    }
}
```

- `$request->file('image')`: obté el fitxer pujat.
- `->store('products', 'public')`: el guarda en el disc public (configurat en `config/filesystems.php`) dins de la carpeta `products/`. Laravel genera un nom únic per al fitxer.
- El resultat (`$path`) és una ruta relativa dins del disc, per exemple: "products/abc123def456.jpg".

En el sistema de fitxers real, això va a: `storage/app/public/products/abc123def456.jpg`

I a través de l'enllaç simbòlic public/storage (si has fet php artisan storage:link) s'hi podrà accedir com: `http://tu-app.test/storage/products/abc123def456.jpg`

**Amb nom personalitzat:**

```php
<?php
// Guardar con nombre original
$path = $request->file('image')->storeAs('products',
                                         $request->file('image')->getClientOriginalName(),
                                         'public' );
```

```php
<?php
// Guardar con nombre personalizado
$fileName = 'product_' . time() . '.' . $request->file('image')->extension();
$path = $request->file('image')->storeAs('products', $fileName, 'public');
```

### 7.4.2. Llegir/Obtindre fitxers

Per a mostrar fitxers guardats en `storage` necessites obtindre la seua URL pública. Laravel proporciona el mètode **`Storage::url()`** i el helper **`asset()`** per a generar URL accessibles.

**Obtindre la URL pública:**

```php
<?php
// En el controlador
$product = Product::find(1);
$url = Storage::url($product->image);  // $url = "/storage/products/abc123def456.jpg"
```

**En Blade:**

```php
<?php
{{ -- Mostrar imagen desde Storage -- }}
<img src="{{ asset('storage/' . $product->image) }}" alt="{{ $product->name }}">
```

```php
<?php
{{ -- ó usando el helper Storage::url() -- }}
<img src="{{ Storage::url($product->image) }}" alt="{{ $product->name }}">
```

**Verificar si un fitxer existix:**

```php
<?php
if (Storage::disk('public')->exists($product->image)) {
    // El archivo existe
    $url = Storage::url($product->image);
} else {
    // Usar imagen placeholder
    $url = asset('images/placeholder.jpg');
}
```

### 7.4.3. Actualitzar fitxers

Quan actualitzes un registre que té un fitxer, has de:

1. Eliminar el fitxer antic (si existix).
2. Guardar el nou fitxer.
3. Actualitzar la ruta en la base de dades.

```php
<?php

public function update(Request $request, Product $product)
{
    $request->validate([
        'name' => 'required|string|max:255',
        'image' => 'nullable|image|mimes:jpeg,png,jpg,gif|max:2048',
    ]);

    // Actualizar datos básicos
    $product->name = $request->name;

    // Si se subió una nueva imagen
    if ($request->hasFile('image')) {
        // 1. Eliminar imagen anterior (si existe)
        if ($product->image && Storage::disk('public')->exists($product->image)) {
            Storage::disk('public')->delete($product->image);
        }

        // 2. Guardar nueva imagen
        $path = $request->file('image')->store('products', 'public');

        // 3. Actualizar la ruta
        $product->image = $path;
    }

    $product->save();

    return redirect()->route('products.show', $product)
        ->with('success', 'Producto actualizado exitosamente');
}
```

### 7.4.4. Eliminar fitxers

Quan elimines un registre que té fitxers associats, també has d'eliminar els fitxers del disc per a evitar fitxers "orfes" que ocupen espai innecessàriament.



```php
<?php

public function destroy(Product $product)
{
    // Eliminar el archivo de Storage
    if ($product->image && Storage::disk('public')->exists($product->image)) {
        Storage::disk('public')->delete($product->image);
    }

    // Eliminar el registro de la base de datos
    $product->delete();

    return redirect()->route('products.index')
        ->with('success', 'Producto eliminado exitosamente');
}
```

## 7.5. Mètodes útils de Storage

A més de les operacions bàsiques, `Storage` proporciona mètodes útils per a verificar, gestionar directoris i copiar o moure fitxers.

### 7.5.1. Verificació de fitxers

Verifica l'existència, la grandària i l'última modificació dels fitxers abans de fer operacions sobre ells.

```php
<?php

// Verificar si existe
Storage::disk('public')->exists('products/image.jpg');

// Verificar si NO existe
Storage::disk('public')->missing('products/image.jpg');

// Obtener tamaño en bytes
Storage::disk('public')->size('products/image.jpg');

// Obtener última modificación (timestamp)
Storage::disk('public')->lastModified('products/image.jpg');
```

### 7.5.2. Gestió de directoris

Crea, llista i elimina directoris per a mantindre els teus fitxers organitzats. Estos mètodes faciliten la gestió de l'estructura de carpetes.

```php
<?php

// Listar archivos en un directorio
$files = Storage::disk('public')->files('products');
// ['products/img1.jpg', 'products/img2.jpg']

// Listar todos los archivos (recursivo)
$files = Storage::disk('public')->allFiles('products');

// Listar directorios
$directories = Storage::disk('public')->directories('products');

// Crear directorio
Storage::disk('public')->makeDirectory('products/featured');

// Eliminar directorio y todo su contenido
Storage::disk('public')->deleteDirectory('products/old');
```

### 7.5.3. Copiar i moure fitxers

Copia o mou fitxers entre directoris sense necessitat de pujar-los de nou. Útil per a reorganitzar contingut o crear còpies de seguretat.

```php
<?php

// Copiar archivo
Storage::disk('public')->copy(
    'products/old-image.jpg',
    'products/backup/old-image.jpg'
);

// Mover archivo
Storage::disk('public')->move(
    'products/temp-image.jpg',
    'products/featured/image.jpg'
);

// Renombrar archivo (es un alias de move)
Storage::disk('public')->move(
    'products/abc123.jpg',
    'products/producto-destacado.jpg'
);
```

## 7.6. Fitxers privats (opcional)

A diferència del disc `public`, que és accessible per a qualsevol, el disc `local` permet emmagatzemar fitxers que **requerixen autenticació** per a ser descarregats.

### 7.6.1. Quan usar fitxers privats?

**Casos d'ús comuns:**

* Factures de clients.
* Documents personals.
* Contractes privats.
* Fitxers de nòmines.
* Qualsevol document sensible que requerisca control d'accés.

### 7.6.2. Guardar fitxers privats

Els fitxers privats es guarden en el disc `local`, que no és accessible directament via web. Has de servir estos fitxers a través de controladors que verifiquen permisos.

```php
<?php

// Guardar en el disco 'local' (privado)
$documentPath = $request->file('invoice')->store('invoices', 'local');

// Se guarda en: storage/app/invoices/
// NO es accesible desde el navegador
```

### 7.6.3. Servir fitxers privats amb control d'accés

Per a servir fitxers privats, necessites un controlador que verifique els permisos:

```php
<?php

namespace App\Http\Controllers;

use App\Models\Invoice;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Storage;
use Symfony\Component\HttpFoundation\StreamedResponse;

class InvoiceController extends Controller
{
    /**
     * Descargar factura privada.
     */
    public function download($id): StreamedResponse
    {
        // 1. Buscar la factura
        $invoice = Invoice::findOrFail($id);
        
        // 2. Verificar que el usuario tiene permiso
        if (auth()->id() !== $invoice->user_id && !auth()->user()->isAdmin()) {
            abort(403, 'No tienes permiso para acceder a este archivo.');
        }
        
        // 3. Verificar que el archivo existe
        if (!Storage::disk('local')->exists($invoice->file_path)) {
            abort(404, 'Archivo no encontrado.');
        }
        
        // 4. Descargar el archivo
        return Storage::disk('local')->download(
            $invoice->file_path,
            $invoice->original_filename  // Nombre del archivo descargado
        );
    }
    
    /**
     * Ver archivo privado en el navegador (sin descargar).
     */
    public function view($id): StreamedResponse
    {
        $invoice = Invoice::findOrFail($id);
        
        // Verificar permisos
        if (auth()->id() !== $invoice->user_id && !auth()->user()->isAdmin()) {
            abort(403, 'No tienes permiso para acceder a este archivo.');
        }
        
        // Mostrar en el navegador (para PDFs, imágenes)
        return Storage::disk('local')->response(
            $invoice->file_path,
            $invoice->original_filename
        );
    }
}
```

**Definir la ruta:**

```php
<?php
// routes/web.php
Route::middleware('auth')->group(function () {
    Route::get('/invoices/{id}/download', [InvoiceController::class, 'download'])
        ->name('invoices.download');
    
    Route::get('/invoices/{id}/view', [InvoiceController::class, 'view'])
        ->name('invoices.view');
});
```

**En la vista:**

```php
<?php
{{ -- Enlace para descargar factura privada -- }}
<a href="{{ route('invoices.download', $invoice->id) }}" 
   class="btn btn-primary">
    Descargar Factura
</a>

{{ -- Enlace para ver en el navegador -- }}
<a href="{{ route('invoices.view', $invoice->id) }}" 
   target="_blank"
   class="btn btn-secondary">
    Ver Factura
</a>
```

**Diferència: download() vs response()**

* **`download()`**: força la descàrrega del fitxer (capçalera `Content-Disposition: attachment`).
* **`response()`**: mostra el fitxer en el navegador (per a PDF, imatges).

## 7.7. Bones pràctiques

Seguir bones pràctiques en la gestió de fitxers és crucial per a la seguretat, el rendiment i la mantenibilitat de la teua aplicació. Estes recomanacions t'ajudaran a evitar problemes comuns.

### 7.7.1. Validar sempre els fitxers

Valida el tipus, la grandària i les dimensions dels fitxers pujats per a previndre fitxers maliciosos, excessivament grans o de formats incorrectes.

```php
<?php

$request->validate([
    'image' => [
        'required',          // Campo obligatorio
        'image',             // Debe ser una imagen
        'mimes:jpeg,png,jpg,gif,webp',  // Tipos permitidos
        'max:2048',          // Tamaño máximo en KB (2MB)
        'dimensions:min_width=100,min_height=100',  // Dimensiones mínimas
    ],
]);
```

### 7.7.2. Advertència de seguretat: extensions de fitxer

Confiar només en l'extensió del fitxer és un error greu de seguretat. Els atacants poden manipular extensions per a intentar pujar codi maliciós.

!!!warning "No confies mai en l'extensió del fitxer"
    Un atacant pot canviar el nom d'un fitxer maliciós `virus.php` a `virus.jpg` per a intentar enganyar el sistema.

**Mesures de seguretat obligatòries:**

1. **Usa sempre la regla `image`**: Laravel valida el contingut real del fitxer (tipus MIME), no només l'extensió.

2. **No executes mai fitxers pujats**: els fitxers pujats per usuaris no s'han d'executar mai directament.

3. **Usa el disc correcte**:

    * Fitxers públics → disc `public` (imatges visibles).
    * Fitxers sensibles → disc `local` (amb control d'accés).
  
4. **Valida el tipus MIME**: `mimes:jpeg,png,jpg,gif` verifica el contingut real.

```php
<?php

// ✅ BUENO: Validación completa

$request->validate([
    'image' => 'required|image|mimes:jpeg,png,jpg,gif|max:2048',
]);
```

```php
<?php

// ❌ MALO: Solo verificar extensión

if (pathinfo($file->getClientOriginalName(), PATHINFO_EXTENSION) === 'jpg') {
    // Un atacante puede renombrar virus.php a virus.jpg
}
```

### 7.7.3. Organitzar fitxers en subdirectoris

Mantín els teus fitxers organitzats en subdirectoris per tipus o data. Això facilita el manteniment, les còpies de seguretat i evita problemes de rendiment amb molts fitxers.


```php
<?php
// ❌ Malo: Todos los archivos en el mismo directorio

Storage::disk('public')->put('image.jpg', $file);
// storage/app/public/image.jpg
```

```php
<?php
// ✅ Bueno: Organizar por tipo

Storage::disk('public')->put('products/image.jpg', $file);
// storage/app/public/products/image.jpg
```

```php
<?php
// ✅ Mejor: Organizar por fecha

$date = now()->format('Y/m');
Storage::disk('public')->put("products/{$date}/image.jpg", $file);
// storage/app/public/products/2025/01/image.jpg
```

### 7.7.4. Eliminar fitxers orfes

Elimina sempre el fitxer quan elimines el registre:

```php
<?php
// ❌ Malo: Solo eliminar el registro

$product->delete();
// El archivo queda en storage ocupando espacio
```

```php
<?php
// ✅ Bueno: Eliminar archivo y registro

if ($product->image && Storage::disk('public')->exists($product->image)) {
    Storage::disk('public')->delete($product->image);
}
$product->delete();
```

### 7.7.5. Usar noms de fitxer únics

Genera noms únics per a evitar col·lisions i sobreescriptures accidentals de fitxers quan diversos usuaris pugen fitxers amb el mateix nom.

```php
<?php
// ❌ Malo: Nombre predecible

$fileName = 'product.jpg';
// Si varios usuarios suben 'product.jpg', se sobrescriben
```

```php
<?php
// ✅ Bueno: Nombre único con timestamp

$fileName = 'product_' . time() . '.' . $request->file('image')->extension();
```

```php
<?php
// ✅ Mejor: Nombre único con UUID

$fileName = Str::uuid() . '.' . $request->file('image')->extension();
```

```php
<?php
// ✅ Automático: Laravel genera nombres únicos con store()

$path = $request->file('image')->store('products', 'public');
// Laravel genera: "products/abc123def456ghi789.jpg"
```

### 7.7.6. Gestionar imatges que falten en les vistes

Gestiona sempre el cas d'imatges que falten o que s'han eliminat mostrant una imatge *placeholder*. Això evita enllaços trencats i millora l'experiència d'usuari.


```php
<?php
{{ -- ❌ Malo: Error si la imagen no existe -- }}

<img src="{{ asset('storage/' . $product->image) }}">
```

```php
<?php
{{ -- ✅ Bueno: Verificar primero -- }}

@if($product->image && Storage::disk('public')->exists($product->image))
    <img src="{{ asset('storage/' . $product->image) }}" alt="{{ $product->name }}">
@else
    <img src="{{ asset('images/placeholder.jpg') }}" alt="Sin imagen">
@endif
```

```php
<?php
{{ -- ✅ Mejor: Usar un accessor en el modelo -- }}

<img src="{{ $product->image_url }}" alt="{{ $product->name }}">
```

**Accessor en el model:**

```php
<?php

namespace App\Models;

use Illuminate\Database\Eloquent\Model;
use Illuminate\Support\Facades\Storage;
use Illuminate\Database\Eloquent\Casts\Attribute;

class Product extends Model
{
    /**
     * Get the product's image URL.
     */
    protected function imageUrl(): Attribute
    {
        return Attribute::make(
            get: function () {
                if ($this->image && Storage::disk('public')->exists($this->image)) {
                    return asset('storage/' . $this->image);
                }
                return asset('images/placeholder.jpg');
            },
        );
    }
}
```

## 7.8. Flux complet: pujada d'imatge en un producte

Este exemple complet integra totes les peces: 

- formulari HTML, 
- controlador amb validació i 
- emmagatzematge i vista per a mostrar la imatge. 

És el patró típic per a gestionar *uploads*.

### 7.8.1. Formulari HTML

El formulari ha d'incloure **`enctype="multipart/form-data"`** i un input de tipus **`file`** per a permetre la pujada de fitxers.

```php
<?php
{{ -- resources/views/admin/products/create.blade.php -- }}

<form action="{{ route('admin.products.store') }}" method="POST" enctype="multipart/form-data">
    @csrf

    <div>
        <label for="name">Nombre del Producto</label>
        <input type="text" id="name" name="name" value="{{ old('name') }}" required>
        @error('name')
            <p class="text-red-500">{{ $message }}</p>
        @enderror
    </div>

    <div>
        <label for="image">Imagen del Producto</label>
        <input type="file" id="image" name="image" accept="image/*" required>
        @error('image')
            <p class="text-red-500">{{ $message }}</p>
        @enderror
    </div>

    <button type="submit">Crear Producto</button>
</form>
```

### 7.8.2. Controlador

El controlador valida el fitxer, el guarda en storage i emmagatzema la ruta en la base de dades. També inclou mètodes per a actualitzar i eliminar imatges correctament.

```php
<?php

namespace App\Http\Controllers;

use App\Models\Product;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Storage;

class ProductController extends Controller
{
    /**
     * Mostrar formulario de creación.
     */
    public function create()
    {
        return view('admin.products.create');
    }

    /**
     * Guardar nuevo producto.
     */
    public function store(Request $request)
    {
        // 1. Validar datos
        $validated = $request->validate([
            'name' => 'required|string|max:255',
            'image' => 'required|image|mimes:jpeg,png,jpg,gif|max:2048',
        ]);

        // 2. Guardar imagen en Storage
        $imagePath = $request->file('image')->store('products', 'public');

        // 3. Crear producto en la base de datos
        $product = Product::create([
            'name' => $validated['name'],
            'image' => $imagePath,
        ]);

        // 4. Redirigir con mensaje de éxito
        return redirect()->route('admin.products.index')
            ->with('success', 'Producto creado exitosamente');
    }

    /**
     * Actualizar producto existente.
     */
    public function update(Request $request, Product $product)
    {
        // 1. Validar datos (imagen opcional en actualización)
        $validated = $request->validate([
            'name' => 'required|string|max:255',
            'image' => 'nullable|image|mimes:jpeg,png,jpg,gif|max:2048',
        ]);

        // 2. Actualizar nombre
        $product->name = $validated['name'];

        // 3. Si se subió nueva imagen
        if ($request->hasFile('image')) {
            // 3a. Eliminar imagen anterior
            if ($product->image && Storage::disk('public')->exists($product->image)) {
                Storage::disk('public')->delete($product->image);
            }

            // 3b. Guardar nueva imagen
            $product->image = $request->file('image')->store('products', 'public');
        }

        // 4. Guardar cambios
        $product->save();

        // 5. Redirigir con mensaje de éxito
        return redirect()->route('admin.products.index')
            ->with('success', 'Producto actualizado exitosamente');
    }

    /**
     * Eliminar producto.
     */
    public function destroy(Product $product)
    {
        // 1. Eliminar imagen de Storage
        if ($product->image && Storage::disk('public')->exists($product->image)) {
            Storage::disk('public')->delete($product->image);
        }

        // 2. Eliminar producto de la base de datos
        $product->delete();

        // 3. Redirigir con mensaje de éxito
        return redirect()->route('admin.products.index')
            ->with('success', 'Producto eliminado exitosamente');
    }
}
```
