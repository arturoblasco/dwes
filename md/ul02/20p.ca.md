???teolaravel "Glossari tècnic"
	| Terme | Definició |
	| --- | --- |
	| **array\_filter()** | Funció PHP que filtra els elements d'un array segons una condició booleana i torna només els que la complixen. |
	| **array\_map()** | Funció PHP que aplica una transformació a cada element d'un array i torna un array nou transformat. |
	| **Blade** | Motor de plantilles de Laravel amb una sintaxi elegant (, `@if`, `@foreach`) que es compila a PHP pur. |
	| **compact()** | Funció PHP que convertix variables en un array associatiu per a passar-les a les vistes (`compact('productos', 'usuario')`). |
	| **Controlador** | Classe que gestiona la lògica de negoci i coordina models i vistes, tornant respostes HTTP. |
	| **Controlador Resource** | Controlador que implementa les 7 accions RESTful estàndard (index, create, store, show, edit, update, destroy). |
	| **Dades mock** | Dades de prova simulades en fitxers PHP (`database/data/`) per a desenvolupar sense una base de dades real. |
	| **Directiva Blade** | Instrucció especial de Blade (`@if`, `@foreach`, `@auth`, `@csrf`, etc.) que controla el flux i la lògica a les plantilles. |
	| **Herència de plantilles** | Mecanisme de Blade (`@extends`, `@section`, `@yield`) que permet que les vistes filles estenguen layouts pares. |
	| **Layout** | Plantilla mestra que definix l'estructura comuna (header, footer, scripts) de diverses pàgines d'una aplicació. |
	| **Middleware** | Capa de programari que filtra/processa les peticions HTTP abans que arriben als controladors (autenticació, CORS, etc.). |
	| **Operador null-safe** | Operador `?.` de PHP que evita errors en accedir a propietats/mètodes d'objectes que poden ser nuls. |
	| **Ruta** | Definició a `web.php` o `api.php` que especifica com ha de gestionar l'aplicació Laravel una URL. |
	| **Secció** | Àrea definida amb `@section`/`@yield` en un layout que les vistes filles poden sobreescriure (`@show`), ampliar (`@append`) o modificar. |
	| **Service Container** | Contenidor de dependències que gestiona la creació i la resolució automàtica d'objectes en Laravel (IoC Container). |
	| **Stack** | Mecanisme de Blade (`@push`, `@stack`) per a acumular contingut (scripts, estils) des de diverses vistes en un layout. |
	| **Trait** | Mecanisme de PHP de reutilització horitzontal de codi que permet compartir mètodes entre classes sense herència. |
	| **View Composer** | Classe que injecta dades automàticament en vistes concretes sense repetir codi als controladors. |
	| **View::share()** | Mètode per a compartir dades globalment amb totes les vistes de l'aplicació. |



???teolaravel "FAQ (preguntes freqüents sobre la pràctica)"
	- **Error "Target class [NombreController] does not exist" en accedir a una ruta**

        Verifica els passos següents:

        - El controlador existix a `app/Http/Controllers/`
        - El nom del fitxer i el de la classe coincidixen exactament (distingix majúscules i minúscules)
        - El namespace és correcte (`namespace App\Http\Controllers;`)
        - Executa `php artisan route:clear` per a netejar la memòria cau de rutes
        - Verifica que has importat el controlador a `web.php` amb `use App\Http\Controllers\NombreController;`
	- **Error "View [nombre-vista] not found" en carregar una pàgina**

        Verifica els passos següents:

        - El fitxer existix a `resources/views/` amb l'extensió `.blade.php`
        - La ruta és correcta (Laravel utilitza el punt per als subdirectoris: `categories.show` = `resources/views/categories/show.blade.php`)
        - El nom del fitxer no té majúscules (Laravel distingix majúscules i minúscules en Linux/Docker)
        - Executa `php artisan view:clear` per a netejar la memòria cau
	- **Les dades mock tornen "Undefined array key" o valors nuls**

        Verifica els passos següents:

        - Els fitxers mock existixen a `database/data/` i tornen un array amb `return [...]`
        - Les claus de l'array coincidixen amb els ID que busques
        - Al trait `LoadsMockData` la ruta del `require` és correcta (`database_path('data/mock-products.php')`)
        - El mètode `enrichProductsWithOffers()` es crida abans de passar les dades a la vista
	- **El mètode `enrichProductsWithOffers()` no funciona o mostra dades incorrectes**

        Este mètode ha de complir els passos següents:

        - Carregar primer les ofertes amb `$this->loadOffers()`
        - Utilitzar `array_map()` per a transformar cada producte
        - Buscar l'oferta a l'array d'ofertes per `$product['offer_id']`
        - Calcular `final_price` correctament: `price * (1 - discount_percentage / 100)`
        - Verifica que els `offer_id` dels productes coincidixen amb ID reals de `mock-offers.php`
	- **Error "Call to undefined method" en utilitzar el trait LoadsMockData**

        Verifica els passos següents:

        - El trait està declarat al controlador amb `use LoadsMockData;` (dins de la classe)
        - El namespace del trait és correcte (`namespace App\Traits;`)
        - Has importat el trait al controlador amb `use App\Traits\LoadsMockData;` (fora de la classe)
        - El mètode que crides existix al trait (revisa majúscules/minúscules)
	- **Els components Blade (`ProductCard`, `CategoryCard`) no es mostren o donen error**

        Verifica els passos següents:

        - Has creat els dos fitxers: la classe a `app/View/Components/` i la vista a `resources/views/components/`
        - Els noms coincidixen (PascalCase a la classe, kebab-case a la vista: `ProductCard.php` → `product-card.blade.php`)
        - La classe estén `Component` i té el mètode `render()`
        - Les props (`$product`, `$category`) estan definides al constructor
        - Executa `php artisan view:clear` per a netejar la memòria cau
	- **El layout `app.blade.php` no carrega els partials (header, footer, navigation)**

        Verifica els passos següents:

        - Els partials existixen a `resources/views/partials/` amb l'extensió `.blade.php`
        - La sintaxi d'inclusió és correcta: `@include('partials.header')` (punt, no barra)
        - No hi ha errors de sintaxi als partials (un error en un partial trenca tota la pàgina)
        - Els partials tornen HTML vàlid
	- **Error 404 "Page not found" en accedir a rutes que he definit a `web.php`**

        Verifica els passos següents:

        - La ruta està definida correctament a `routes/web.php`
        - La URL coincidix exactament (revisa els paràmetres: `/products/{id}` requerix un ID numèric)
        - Executa `php artisan route:list` per a veure totes les rutes disponibles
        - El nom de la ruta és correcte si utilitzes `route('nombre')`
        - Neteja la memòria cau amb `php artisan route:clear`
	- **Els estils de Tailwind no s'apliquen a les vistes noves**

        Verifica els passos següents:

        - El layout `app.blade.php` inclou `@vite(['resources/css/app.css'])`
        - Les vistes filles estenen el layout amb `@extends('layouts.app')`
        - Has executat `sail npm run build` o `sail npm run dev` després de crear vistes noves
        - Les classes de Tailwind estan ben escrites (sense espais: `bg-blue-500`, no `bg-blue - 500`)
	- **Error "Trying to access array offset on value of type null" a les vistes**

        Utilitza operadors null-safe seguint estos passos:

        - Per a arrays: `$product['offer'] ?? null`
        - Per a objectes: `$user?->name`
        - En Blade: `@isset($variable)` abans d'utilitzar-la
        - Verifica que el controlador passa totes les dades necessàries amb `dd($datos)`
	- **La navegació no ressalta correctament l'enllaç actiu**

        Verifica els passos següents:

        - Les rutes tenen noms assignats amb `->name('nombre.ruta')`
        - A `navigation.blade.php` utilitzes `Route::is('nombre.ruta')` o `request()->routeIs('nombre.ruta')`
        - Els noms de ruta coincidixen exactament (distingix majúscules i minúscules)
        - Per a rutes amb paràmetres utilitza comodins: `Route::is('products.*')`
	- **Error "Route [nombre.ruta] not defined" en utilitzar `route()` a les vistes**

        Verifica els passos següents:

        - La ruta té un nom assignat a `web.php` amb `->name('nombre.ruta')`
        - El nom no té errors tipogràfics
        - Executa `sail artisan route:list` per a veure totes les rutes amb els seus noms
        - Neteja la memòria cau amb `sail artisan route:clear` i `sail artisan config:clear`
	- **Els productes no mostren el preu amb el descompte aplicat**

        Verifica els passos següents:

        - Crides `enrichProductsWithOffers()` al controlador ABANS de passar les dades a la vista
        - El producte té un `offer_id` vàlid a `mock-products.php`
        - L'oferta existix a `mock-offers.php` amb eixe ID
        - El càlcul és correcte: `final_price = price * (1 - discount_percentage / 100)`
        - Utilitzes `$product['final_price']` a la vista, no hi fas el càlcul
	- **Com puc depurar quines dades rep la meua vista?**

        Utilitza estes tècniques de depuració:
        
        - Al controlador: `dd($productos)` abans de `return view()` per a veure les dades
        - A la vista: `{{ dd($productos) }}` o `@dump($productos)` per a inspeccionar-les
        - Laravel Telescope → Requests → Veure les dades passades a la vista
        - Navegador → Veure el codi font per a verificar l'HTML generat


### Objectiu
L'objectiu d'esta pràctica és construir una botiga en línia completa amb Laravel, implementant el patró MVC (Model-Vista-Controlador). Es crearan rutes públiques, controladors per a gestionar la lògica de negoci i vistes Blade per a mostrar les dades de manera dinàmica.

### Filosofia de treball
Esta pràctica està dissenyada per a ser genèrica i personalitzable. A partir de la temàtica triada en la pràctica anterior, s'adaptaran tots els noms, categories i productes segons el tipus de botiga.

### FASE 2: Crear els fitxers de dades mock

#### 1. Crear el directori de dades mock
Hem decidit estructurar les dades mock com un array d'arrays (una matriu) en PHP perquè esta estructura és senzilla i fàcil de manipular. Cada element de l'array principal representa una entitat (per exemple, una categoria o un producte) i s'identifica per la seua clau numèrica o pel seu ID. Dins de cada element s'utilitza un array associatiu per a emmagatzemar els diferents atributs de l'entitat (com `id`, `name`, `description`, etc.). Esta manera d'organitzar-les facilita la lectura, la cerca i la modificació de les dades mock durant el desenvolupament.

En este projecte crearem diversos fitxers de dades mock per a centralitzar la informació de prova. Els principals mocks que crearem són:

- **mock-categories.php**: contindrà les categories de productes.
- **mock-products.php**: inclourà els productes de la botiga.
- **mock-offers.php**: definirà les ofertes disponibles per als productes.
- **mock-cart.php**: simularà l'estat del carret de la compra.

#### 2. Crear el fitxer de categories
Els diferents atributs d'una categoria solen ser:

- **id**: identificador únic de la categoria.
- **name**: nom de la categoria.
- **slug**: identificador amigable per a URL (per exemple, "electronica", "ropa-hombre").

- **parent_id**: si la categoria és filla d'una altra, este camp indica la categoria pare.

#### 3. Crear el fitxer d'ofertes

### FASE 3: Crear el trait per a carregar les dades mock

En esta secció crearem un trait anomenat **`LoadsMockData`** que ens permetrà carregar fàcilment les dades simulades (mock) de categories, ofertes, productes i carret des dels fitxers PHP ubicats a `database/data/`.

Este trait s'utilitzarà als controladors per a accedir a les dades d'exemple sense necessitat d'una base de dades real, cosa que facilita el desenvolupament i les proves de la botiga en línia.

L'objectiu és centralitzar la càrrega de dades mock i reutilitzar este codi en qualsevol controlador que el necessite.

A més, este trait inclourà un mètode auxiliar (helper) anomenat `enrichProductsWithOffers()` que serà fonamental per a preparar les dades abans d'enviar-les a les vistes. Este mètode:

1. **Enriquix cada producte** amb les dades completes de la seua oferta (nom, percentatge de descompte).
2. **Calcula el preu final** aplicant el descompte corresponent.
3. **Evita escriure valors fixos (hardcode)** a les vistes i als components.

D'esta manera, el component `ProductCard` rebrà tota la informació necessària sense haver de fer càlculs ni cerques a la vista.

### FASE 6: Crear el sistema de layouts, partials i components

#### 1. Crear l'estructura de directoris

Implementarem un **sistema híbrid modern** que combina el millor de tres enfocaments complementaris:

* **Layout mestre**: definix l'estructura general de la pàgina (HTML, head, body) i permet incloure contingut dinàmic mitjançant seccions (`@yield`, `@section`). És com l'"esquelet" de totes les pàgines.
* **Partials**: són fragments HTML senzills per a elements fixos com el head, el header, el footer, la navegació, etc. Són útils per a elements que no necessiten una lògica complexa.
* **Components Blade**: permeten encapsular blocs d'interfície reutilitzables i parametritzables (targetes de producte, alertes, botons, etc.). Són com "peces de LEGO" que es poden combinar i personalitzar.

Crea l'estructura de directoris:

```bash
mkdir -p resources/views/layouts
mkdir -p resources/views/partials
mkdir -p resources/views/components
```

    2. **Organització**: incloure un títol per a cada captura que explique què mostra
    3. **Qualitat**: les captures han de ser clares i llegibles
    4. **Personalització**: la botiga ha de reflectir clarament la temàtica triada amb dades personalitzades
    5. **Funcionalitat**: totes les rutes i la navegació han de funcionar correctament
    6. **Terminal**: totes les captures han d'incloure el prompt del terminal visible
    7. **Completesa**: s'han de mostrar totes les vistes creades (inici, productes, categories, ofertes, carret, contacte)
    8. **Dades personalitzades**: els productes, les categories i les ofertes han d'estar adaptats a la teua temàtica concreta
