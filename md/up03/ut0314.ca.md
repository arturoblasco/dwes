# <img src="../../img/php_azul.svg" width="40"> 3.14. Gestió d'errors

Durant l'execució d'una aplicació poden aparéixer problemes: intentar obrir un fitxer que no existix, utilitzar una variable sense inicialitzar o realitzar una operació no vàlida.

**Gestionar estos problemes implica detectar-los, conéixer-ne la causa i decidir com ha de respondre l'aplicació.** Amagar un missatge no soluciona l'error que l'ha provocat.

Convé distingir **quins errors es notifiquen, on es mostren i com reaccionem davant d'ells**.

## 1. Nivells d'error

PHP classifica els seus missatges d'error mitjançant constants. Algunes de les més habituals són:

| Constant | Significat | Continua el programa? |
| --- | --- | --- |
| `E_ERROR` | Error fatal durant l'execució, com esgotar la memòria disponible. | No. |
| `E_WARNING` | Advertència: una operació ha fallat, però PHP pot continuar. | Sí. |
| `E_NOTICE` | Avís sobre una situació que pot indicar un problema. | Sí. |
| `E_PARSE` | Error de sintaxi detectat en analitzar el codi. | El fitxer afectat no arriba a executar-se. |
| `E_DEPRECATED` | Avís d'ús d'una característica obsoleta que convé substituir. | Sí. |

**`E_ALL` representa tots els nivells**, per la qual cosa s'utilitza per a configurar el report complet d'errors.

> **Atenció als exemples antics**
>
> En PHP 8, utilitzar una variable no definida genera un `E_WARNING`; abans generava un `E_NOTICE`.

Podeu consultar el [llistat complet de constants en el manual de PHP][constantes]{:target="_blank"} i els [canvis introduïts en PHP 8][migracion-php8]{:target="_blank"}.

## 2. Notificar, mostrar i registrar

Són decisions diferents:

| Configuració | Pregunta que respon |
| --- | --- |
| `error_reporting` | Quins nivells d'error volem notificar? |
| `display_errors` | S'inclouen els seus missatges en l'eixida enviada a l'usuari? |
| `log_errors` | Es guarden els errors en un registre? |
| `error_log` | En quin fitxer o destinació es registren? |


???examplephp "Exemple"
    Per exemple, podem **registrar els errors sense mostrar-los en la pàgina web**. Així, l'equip de desenvolupament disposa d'informació per a investigar-los i el visitant no veu detalls interns del servidor.

    Estes opcions es poden configurar en `php.ini`.
	=== "Durant el desenvolupament"
        Una configuració útil és:

        ```ini
        error_reporting = E_ALL
        display_errors = On
        log_errors = On
        ```
	=== "En producció"
        Una configuració habitual és:

        ```ini
        error_reporting = E_ALL
        display_errors = Off
        log_errors = On
        ```

> **Mostrar i registrar són coses diferents**
>
> Desactivar `display_errors` no evita que el problema ocórrega ni impedix registrar-lo.

Més informació: [configuració d'errors en el manual de PHP][configuracion]{:target="_blank"}.

## 3. Configuració mitjançant codi

També podem canviar determinades opcions durant l'execució:

```php
<?php

error_reporting(E_ALL);

ini_set("display_errors", "1");
ini_set("log_errors", "1");
```

Estos canvis afecten l'execució actual; no modifiquen permanentment `php.ini`. A més, una instrucció del mateix fitxer no es pot executar si un error de sintaxi impedix analitzar-lo.

Per a seleccionar nivells utilitzem **operadors a nivell de bits**:

```php
// Notificar todos los niveles.
error_reporting(E_ALL);

// Notificar todos excepto los avisos E_NOTICE.
error_reporting(E_ALL & ~E_NOTICE);

// Notificar únicamente errores fatales y advertencias.
error_reporting(E_ERROR | E_WARNING);

// Desactivar el reporte del manejador estándar.
error_reporting(0);
```

En estes expressions:

- **`|`** inclou diversos nivells.
- **`~`** invertix una màscara; juntament amb `&`, permet excloure nivells.
- **`&`** conserva els nivells que coincidixen en ambdues màscares.

???examplephp "Exemple"

    ```php
    E_ALL & ~E_NOTICE
    ```

    Significa: **tots els nivells excepte `E_NOTICE`**. No s'ha de confondre `&` amb l'operador lògic `&&`.

Durant el desenvolupament convé utilitzar `E_ALL` per a detectar també els problemes que no interrompen el programa.

Més informació: [`error_reporting()` en el manual de PHP][error-reporting]{:target="_blank"}.

## 4. Gestors personalitzats

PHP disposa d'un gestor estàndard per als seus errors. Amb **`set_error_handler()`** podem registrar una funció pròpia per a determinats nivells, per exemple, per a canviar el format del missatge o registrar-lo d'una altra manera.

???examplephp "Exemple didàctic per a desenvolupament"

    ```php
    <?php

    error_reporting(E_ALL);

    function miManejadorErrores(int $nivel, string $mensaje): bool
    {
        // Respetar los niveles seleccionados en error_reporting().
        if ((error_reporting() & $nivel) === 0) {
            return false;
        }

        echo "<strong>Advertencia:</strong> "
            . htmlspecialchars($mensaje, ENT_QUOTES, "UTF-8")
            . "<br>";

        return true;
    }

    // Utilizar nuestra función para las advertencias E_WARNING.
    set_error_handler("miManejadorErrores", E_WARNING);

    // Si el archivo no existe, se genera una advertencia.
    $archivo = fopen("archivo_inexistente.txt", "r");

    if ($archivo === false) {
        echo "No se ha podido abrir el archivo.<br>";
    }

    echo "El programa continúa.<br>";

    // Recuperar el manejador anterior.
    restore_error_handler();
    ```

    En este exemple:

    1. `set_error_handler()` registra la funció; **no l'executa immediatament**.
    2. Si `fopen()` genera un `E_WARNING`, PHP crida la funció.
    3. `$nivel` conté el tipus d'error i `$mensaje`, la seua descripció.
    4. `return true` indica que l'hem gestionat; `return false` deixa actuar el gestor estàndard.
    5. `restore_error_handler()` recupera el gestor anterior.

La comprovació d'`error_reporting()` és necessària si volem respectar eixe filtre: **un gestor personalitzat pot rebre nivells exclosos del report estàndard**. Tampoc no pot gestionar tots els errors; per exemple, no gestiona `E_ERROR` ni `E_PARSE`.

> **Gestors personalitzats i producció**
>
> L'`echo` del gestor és una eixida escrita pel nostre codi: `display_errors = Off` no l'amaga. En producció, podem utilitzar `error_log()` per a registrar el detall i mostrar a l'usuari un missatge general.

Més informació: [`set_error_handler()`][set-error-handler], [`restore_error_handler()`][restore-error-handler] i [`error_log()`][error-log] en el manual de PHP.

## 5. Diferència amb les excepcions i els objectes `Error`

**`set_error_handler()` no substituïx `try/catch`.** En PHP modern, alguns problemes es comuniquen mitjançant objectes llançats que hem de capturar.

Per exemple, en PHP 8, dividir mitjançant `/` entre zero llança un **`DivisionByZeroError`**, que no passa pel nostre gestor d'advertències:

```php
<?php

$dividendo = 10;
$divisor = 0;

try {
    $resultado = $dividendo / $divisor;
    echo "Resultado: $resultado";
} catch (DivisionByZeroError $e) {
    echo "No se puede dividir entre cero.";
}

echo "<br>El programa continúa.";
```

**Capturar el problema permet decidir com continuar.** En canvi, canviar `error_reporting()` només en configura el report: no convertix una operació incorrecta en una operació vàlida.

Més informació: [`DivisionByZeroError` en el manual de PHP][division-by-zero].
