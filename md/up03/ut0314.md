# <img src="../../img/php_azul.svg" width="40"> 3.14. Gestión de errores

Durante la ejecución de una aplicación pueden aparecer problemas: intentar abrir un archivo que no existe, utilizar una variable sin inicializar o realizar una operación no válida.

**Gestionar estos problemas implica detectarlos, conocer su causa y decidir cómo debe responder la aplicación.** Ocultar un mensaje no soluciona el error que lo ha provocado.

Conviene distinguir **qué errores se notifican, dónde se muestran y cómo reaccionamos ante ellos**.

## 1. Niveles de error

PHP clasifica sus mensajes de error mediante constantes. Algunas de las más habituales son:

| Constante | Significado | ¿Continúa el programa? |
| --- | --- | --- |
| `E_ERROR` | Error fatal durante la ejecución, como agotar la memoria disponible. | No. |
| `E_WARNING` | Advertencia: una operación ha fallado, pero PHP puede continuar. | Sí. |
| `E_NOTICE` | Aviso sobre una situación que puede indicar un problema. | Sí. |
| `E_PARSE` | Error de sintaxis detectado al analizar el código. | El archivo afectado no llega a ejecutarse. |
| `E_DEPRECATED` | Aviso de uso de una característica obsoleta que conviene sustituir. | Sí. |

**`E_ALL` representa todos los niveles**, por lo que se utiliza para configurar el reporte completo de errores.

> **Atención a los ejemplos antiguos**
>
> En PHP 8, utilizar una variable no definida genera un `E_WARNING`; anteriormente generaba un `E_NOTICE`.

Podéis consultar el [listado completo de constantes en el manual de PHP][constantes]{:target="_blank"} y los [cambios introducidos en PHP 8][migracion-php8]{:target="_blank"}.

## 2. Notificar, mostrar y registrar

Son decisiones distintas:

| Configuración | Pregunta que responde |
| --- | --- |
| `error_reporting` | ¿Qué niveles de error queremos notificar? |
| `display_errors` | ¿Se incluyen sus mensajes en la salida enviada al usuario? |
| `log_errors` | ¿Se guardan los errores en un registro? |
| `error_log` | ¿En qué archivo o destino se registran? |


???examplephp "Ejemplo"
    Por ejemplo, podemos **registrar los errores sin mostrarlos en la página web**. Así, el equipo de desarrollo dispone de información para investigarlos y el visitante no ve detalles internos del servidor.

    Estas opciones pueden configurarse en `php.ini`.
	=== "Durante el desarrollo"
        Una configuración útil es:

        ```ini
        error_reporting = E_ALL
        display_errors = On
        log_errors = On
        ```
	=== "En producción"
        Una configuración habitual es:

        ```ini
        error_reporting = E_ALL
        display_errors = Off
        log_errors = On
        ```

> **Mostrar y registrar son cosas diferentes**
>
> Desactivar `display_errors` no evita que el problema ocurra ni impide registrarlo.

Más información: [configuración de errores en el manual de PHP][configuracion]{:target="_blank"}.

## 3. Configuración mediante código

También podemos cambiar determinadas opciones durante la ejecución:

```php
<?php

error_reporting(E_ALL);

ini_set("display_errors", "1");
ini_set("log_errors", "1");
```

Estos cambios afectan a la ejecución actual; no modifican permanentemente `php.ini`. Además, una instrucción del propio archivo no puede ejecutarse si un error de sintaxis impide analizarlo.

Para seleccionar niveles utilizamos **operadores a nivel de bits**:

```php
// Notificar todos los niveles.
error_reporting(E_ALL);

// Notificar todos excepto los avisos E_NOTICE.
error_reporting(E_ALL & ~E_NOTICE);

// Notificar únicamente errores fatales y advertencias.
error_reporting(E_ERROR | E_WARNING);

// Desactivar el reporte del manejador estándar.
error_reporting(0);
```

En estas expresiones:

- **`|`** incluye varios niveles.
- **`~`** invierte una máscara; junto con `&`, permite excluir niveles.
- **`&`** conserva los niveles que coinciden en ambas máscaras.

???examplephp "Ejemplo"

    ```php
    E_ALL & ~E_NOTICE
    ```

    Significa: **todos los niveles excepto `E_NOTICE`**. No debe confundirse `&` con el operador lógico `&&`.

Durante el desarrollo conviene utilizar `E_ALL` para detectar también los problemas que no interrumpen el programa.

Más información: [`error_reporting()` en el manual de PHP][error-reporting]{:target="_blank"}.

## 4. Manejadores personalizados

PHP dispone de un manejador estándar para sus errores. Con **`set_error_handler()`** podemos registrar una función propia para determinados niveles, por ejemplo, para cambiar el formato del mensaje o registrarlo de otra manera.

???examplephp "Ejemplo didáctico para desarrollo"

    ```php
    <?php

    error_reporting(E_ALL);

    function miManejadorErrores(int $nivel, string $mensaje): bool
    {
        // Respetar los niveles seleccionados en error_reporting().
        if ((error_reporting() & $nivel) === 0) {
            return false;
        }

        echo "<strong>Advertencia:</strong> "
            . htmlspecialchars($mensaje, ENT_QUOTES, "UTF-8")
            . "<br>";

        return true;
    }

    // Utilizar nuestra función para las advertencias E_WARNING.
    set_error_handler("miManejadorErrores", E_WARNING);

    // Si el archivo no existe, se genera una advertencia.
    $archivo = fopen("archivo_inexistente.txt", "r");

    if ($archivo === false) {
        echo "No se ha podido abrir el archivo.<br>";
    }

    echo "El programa continúa.<br>";

    // Recuperar el manejador anterior.
    restore_error_handler();
    ```

    En este ejemplo:

    1. `set_error_handler()` registra la función; **no la ejecuta inmediatamente**.
    2. Si `fopen()` genera un `E_WARNING`, PHP llama a la función.
    3. `$nivel` contiene el tipo de error y `$mensaje`, su descripción.
    4. `return true` indica que lo hemos gestionado; `return false` deja actuar al manejador estándar.
    5. `restore_error_handler()` recupera el manejador anterior.

La comprobación de `error_reporting()` es necesaria si queremos respetar ese filtro: **un manejador personalizado puede recibir niveles excluidos del reporte estándar**. Tampoco puede gestionar todos los errores; por ejemplo, no gestiona `E_ERROR` ni `E_PARSE`.

> **Manejadores personalizados y producción**
>
> El `echo` del manejador es una salida escrita por nuestro código: `display_errors = Off` no lo oculta. En producción, podemos utilizar `error_log()` para registrar el detalle y mostrar al usuario un mensaje general.

Más información: [`set_error_handler()`][set-error-handler], [`restore_error_handler()`][restore-error-handler] y [`error_log()`][error-log] en el manual de PHP.

## 5. Diferencia con las excepciones y los objetos `Error`

**`set_error_handler()` no sustituye a `try/catch`.** En PHP moderno, algunos problemas se comunican mediante objetos lanzados que debemos capturar.

Por ejemplo, en PHP 8, dividir mediante `/` entre cero lanza un **`DivisionByZeroError`**, que no pasa por nuestro manejador de advertencias:

```php
<?php

$dividendo = 10;
$divisor = 0;

try {
    $resultado = $dividendo / $divisor;
    echo "Resultado: $resultado";
} catch (DivisionByZeroError $e) {
    echo "No se puede dividir entre cero.";
}

echo "<br>El programa continúa.";
```

**Capturar el problema permite decidir cómo continuar.** En cambio, cambiar `error_reporting()` solo configura su reporte: no convierte una operación incorrecta en una operación válida.

Más información: [`DivisionByZeroError` en el manual de PHP][division-by-zero].
